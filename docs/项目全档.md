## 1. 背景与目标

### 1.1 要解决什么

自考（高等教育自学考试）英语科目的考生需要刷历年真题。市面上的题库产品要么收费，
要么只是把真题堆成 PDF 让人自己打印，没有"按你的薄弱点出题"这种能力。

这个项目要做的是：把 20 套历年真题结构化进数据库，然后

- **按真题结构随机组卷**做限时模考，交卷即出客观题成绩；
- **按掌握度自适应出题**做不限时的专项练习，答一题给一次反馈；
- 做错的题自动进错题本，连续答对两次才算订正；
- 用 AI 批改作文、分析错因，并给出应试能力预测。

### 1.2 硬约束

这几条约束决定了后面几乎所有技术选择：

| 约束 | 后果 |
|---|---|
| **完全免费** | 不能用付费数据库、付费托管、付费 CDN |
| **公网可访问、支持多人同时使用** | 不能是本地应用，必须有真正的服务端 |
| **数据必须持久** | 排除了免费档用临时磁盘的托管平台 |
| **手机为主要使用场景** | 三种宽度都要适配，且不做 App，只做网页 |
| **仓库公开** | 凭据一律不进代码，只进 Secrets |

第三条排除掉的东西值得单独说：调研时试过 Render 这类免费 Node 托管，它们免费档
的磁盘是临时的，服务休眠重启后本地 SQLite 文件会被清空，**用户账号会随机消失**。
对一个需要保存学习记录的产品来说这是致命的。

## 2. 技术方案

### 2.1 选型与理由

```
                    ┌─────────────────────────────────────┐
   浏览器 ─────────▶│  Cloudflare Workers（同一个域名）    │
   手机/平板/PC     │                                     │
                    │  /api/*  ──▶ Hono 路由 ──▶ D1       │
                    │  其他路径 ──▶ [assets] 静态托管      │
                    │              （React 构建产物）      │
                    └──────────────┬──────────────────────┘
                                   │
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  D1（Cloudflare 托管 SQLite）        │
                    │  20 张表，数据持久                   │
                    └─────────────────────────────────────┘
                                   │
                        AI 调用（教学/OCR）
                                   ▼
                    ┌─────────────────────────────────────┐
                    │  硅基流动（OpenAI 兼容协议）         │
                    │  Qwen3-8B 教学 · DeepSeek-OCR 解析  │
                    └─────────────────────────────────────┘
```

| 层 | 选择 | 版本 | 为什么 |
|---|---|---|---|
| 运行时 | Cloudflare Workers | compat 2024-12-01 | 免费档够用、全球边缘、冷启动快 |
| 数据库 | Cloudflare D1 | — | 免费、**数据持久**、SQLite 方言 |
| Web 框架 | Hono | ^4.6.14 | 为 Workers 设计，体积小 |
| 鉴权 | jose（JWT）+ bcryptjs | ^5.9.6 / ^2.4.3 | Workers 上可用的纯 JS 实现 |
| 前端 | React + Vite | ^18.3.1 / ^6.0.7 | — |
| 路由 | react-router-dom | ^6.28.0 | — |
| 样式 | **手写 CSS** | — | 见下方取舍 |
| 部署 | GitHub Actions + wrangler | ^4.0.0 | 开发沙箱连不上 Cloudflare API |

### 2.2 三处与需求文档不同的实现

需求文档写了一套方案，实现时改了三处，理由记在 `docs/prd.md` §12.3：

**一、不用 Tailwind，手写 CSS。** 项目只有 20 个页面、一套设计语言，引入 Tailwind
的构建配置和类名心智负担超过收益。`web/src/styles.css` 433 行覆盖全部样式。

**二、能力评估不画雷达图，改成条形。** 七个部分要读的是"各部分得分率谁高谁低"，
这属于比较量值。条形可以直接对比；雷达图轴序任意、面积会放大差异，同样的数据更
难读。

**三、条形图用 HTML 而不是 SVG。** SVG 里的字号会随 viewBox 缩放，实测在 390px 的
手机上 12px 的字只剩 7.7px，根本看不清。改成 HTML 后字号由 CSS 决定，实测 13px。
折线仍用 SVG，但 viewBox 从 520 收到 360，手机上缩放比 0.92，最小字号实测 10.1px。

### 2.3 单域名同时托管前后端

`worker/wrangler.toml` 里这段是关键：

```toml
[assets]
directory = "./public"
not_found_handling = "single-page-application"
run_worker_first = ["/api/*"]
```

- `not_found_handling` 让所有前端路由回落到 `index.html`，这样 `/app/wrongbook`
  这种前端路由直接访问也能打开。
- `run_worker_first` 保证 `/api/*` 永远交给 Worker，**不被 SPA 回落吃掉**。少了这
  一行，未知接口会返回 HTML 而不是 JSON 404，前端拿到一坨 HTML 去 `JSON.parse`。
  线上验证里专门有一条断言守这个行为。

## 3. 数据管线

### 3.1 从 PDF 到数据库

```
原始真题 PDF（扫描件，图片，无文字层）
        │
        │ ① DeepSeek-OCR 逐页转文字
        ▼
   纯文本（排版混乱、选项可能同行）
        │
        │ ② Qwen3-8B 按 PARSING_GUIDE.md 的 schema 结构化
        ▼
data/exams/*.json（20 个文件，人工核对过）
        │
        │ ③ node scripts/build-seed-sql.mjs
        ▼
worker/seed/*.sql（21 个文件：1 个考点 + 20 套卷）
        │
        │ ④ wrangler d1 execute --file（流水线自动）
        ▼
        D1
```

**为什么分两段 AI 而不是一个视觉模型直接出 JSON**：DeepSeek-OCR 是文档文字模型，
不是通用视觉语言模型。让它只做"图片转文字"这一件事，再交给 Qwen3-8B 做结构化，
两段各自可验证。第二段的提示词必须容忍 OCR 产生的不一致换行（同行选项有时会被
拆行，有时不会）。

原始 PDF 没有进仓库（体积大且有版权顾虑），所以 ③④ 可复现，①② 需要重新准备原始
文件。已解析出的 20 个 JSON 是仓库里的事实来源。

### 3.2 数据规模（从数据实测）

| 指标 | 值 |
|---|---|
| 试卷 | 20 套 |
| 题目 | 1020 道 |
| 考点标签 | 21 个 |
| 被存疑记录点名、不参与组卷 | 125 道 |
| 可参与组卷 | 895 道 |
| 解析存疑记录 | 79 条 |

### 3.3 "存疑"机制

解析 AI 对自己不确定的地方必须如实记录（`PARSING_GUIDE.md` §4），产出 79 条
`parsingNotes`。`build-seed-sql.mjs` 从记录文本里正则解析题号（`第N题`、`第N-M题`
这类），把对应题目标成 `存疑`：

```js
function flaggedOrders(exam) {
  const flagged = new Set();
  for (const note of exam.parsingNotes || []) {
    for (const m of note.matchAll(/第\s*(\d+)\s*[-–—~至]\s*(\d+)\s*题/g)) { … }
    for (const m of note.matchAll(/第\s*(\d+)\s*题/g)) flagged.add(Number(m[1]));
  }
  return flagged;
}
```

抽题只认 `已发布`，所以这些题不会被抽到。又因为组卷以"篇章"为单位、一篇少一题就
凑不满模板题量，**被扣下的题会带着整个篇章一起落选**，不会把阅读原文拆散。

动手前量过影响：扣完之后七个部分分别还剩 9 到 20 篇完整篇章，组卷仍然成立。

### 3.4 课程合并

`00015`《英语(二)》与 `13000`《英语(专升本)》是同一门课的前后两个代码。JSON 里保留
每份卷子印的原始代码，**入库时统一归到 13000**（`migrations/0004_merge_courses.sql`
+ 种子生成时的 `COURSE_ALIAS`），这样组卷和练习面对的是一个完整题库。

界面上课程数为 1 时不显示课程选择器，但判断条件写的是"课程数 > 1 才显示"，不是把
13000 硬编码进页面——将来真加第二门课不用回头改。

## 4. 数据库设计

20 张表，按职责分四组。完整字段见 `worker/migrations/*.sql`。

### 4.1 账号与安全（0001、0003）

| 表 | 作用 |
|---|---|
| `users` | 账号、bcrypt 密码哈希、角色（SUPER_ADMIN / USER）、禁用标志、最后登录时间 |
| `login_attempts` | 登录失败计数与锁定截止时间。连续 5 次失败锁 10 分钟 |

### 4.2 题库（0002、0004）

| 表 | 作用 |
|---|---|
| `courses` | 课程、考试时长（150 分钟）、满分（100） |
| `exams` | 试卷（年月、来源文件、发布状态） |
| `sections` | 篇章：类型、原文、写作提示、每题分值 |
| `questions` | 题目：题干、选项（JSON 数组）、答案、官方解析、难度、**状态** |
| `knowledge_points` | 21 个考点标签 |
| `question_knowledge_points` | 题目↔考点，多对多（**一题可挂多个考点**） |
| `exam_parsing_notes` | 79 条解析存疑记录及是否已处理 |
| `exam_templates` | 组卷模板：七个部分的题量与分值 |

`questions.status` 取三值：`草稿` / `已发布` / `存疑`。抽题只认 `已发布`。

### 4.3 作答与学情（0005、0007）

| 表 | 作用 |
|---|---|
| `attempts` | 一次模考或练习会话：模式、状态、难度倾向、客观题分、总分、待 AI 处理数 |
| `attempt_questions` | 这次会话出了哪些题、顺序 |
| `answer_records` | 逐题作答：答案、对错、得分、AI 是否判过、AI 评语 |
| `user_knowledge_mastery` | 每人每考点的对错次数、连对次数、最近一次结果 |
| `wrong_items` | 错题本：错误次数、连对次数、是否已订正、AI 错因与记忆要点、AI 状态 |
| `assessments` | 能力评估快照 |

### 4.4 配置与运维（0002、0006）

| 表 | 作用 |
|---|---|
| `ai_settings` | AI 供应商配置。**API Key 加密存储**，读出一律脱敏 |
| `ai_usage_logs` | 每次 AI 调用的 token、延迟、成败、错误信息 |
| `system_settings` | 可后台调整的算法参数（见下） |
| `seed_state` | 每个种子文件已导入的内容指纹，用来跳过没变的文件 |

可调参数（`system_settings` 初始值）：

```
practice.diagnostic_batch_size   = 40   摸底阶段单批最多覆盖的考点数
practice.reinforce_recent_window = 20   强化阶段避免重复出题的最近题目数窗口
exam.recent_passage_avoid        = 3    组卷时规避最近 N 次模考出现过的篇章
```

## 5. 后端结构与核心算法

`worker/src/` 约 2984 行。`index.js` 挂载路由，`lib/` 放算法，`routes/` 放接口。

### 5.1 路由组织

```js
app.route('/api', examRouter);       // 组卷、答题、交卷、报告、历史
app.route('/api', practiceRouter);   // 专项练习
app.route('/api', studyRouter);      // 错题本、能力评估、AI 触发
admin.route('/bank', bankRouter);    // 题库校对与发布
admin.route('/ai', aiRouter);        // AI 配置与用量
admin.route('/stats', adminStatsRouter);
app.route('/api/admin', admin);
```

共 50 个接口。**鉴权中间件按前缀挂，绝不挂在 `/api/*` 上**——那样会把
`/api/health` 和 `/api/auth/login` 也挡住，导致健康检查和登录全挂。这是
`lib/auth.js` 被单独抽出来的原因。

### 5.2 组卷（`lib/paper.js`，160 行，PRD §7.1）

**抽题单位是篇章而不是单题**，因为阅读类拆开就没有语境了。一篇只有在它的已发布
题量正好等于模板要求时才算候选。

算法：对七个部分逐个挑篇章，用贪心策略让**新增考点重叠最小**；按难度倾向加权；
避开最近 3 次模考出现过的篇章。凑不满就返回 422 `insufficient_questions`，不返回
一套残缺的卷子。

### 5.3 专项练习（`lib/practice.js`，198 行，PRD §7.2）

三阶段，系统自动切换：

| 阶段 | 策略 |
|---|---|
| 摸底 | 每个考点先出一道，尽快把缺陷面铺开 |
| 强化 | 按掌握度加权抽考点 |
| 单考点专项 | 把指定考点下的题挨个做一遍 |

抽题权重（`lib/mastery.js` 的 `tagWeight`）：

| 状态 | 权重 |
|---|---|
| 从未测过 | 2.0 |
| 最近一次答错 | **5.0** |
| 连对 ≤1 次 | 2.0 |
| 连对 2 次 | 1.0 |
| 连对 ≥3 次 | **0.3（保底不为零）** |

最后一行是有意的：连对三次也不彻底移出候选池，**"蒙对"的考点还会被复验**。

练习排除作文：作文没有 AI 批改就判不出对错，出出来会被记成答错，还会污染掌握度。

### 5.4 客观题判分（`lib/grade.js`，89 行，PRD §4.3）

选择题精确匹配选项字母。完形/填词按官方评分参考：语法或拼写错误均不给分、**英美
拼写均可接受**、大小写不扣分，且只有满分或零分，没有部分分。

英美拼写用一张显式对照表，外加只有三条安全规则（`-ise/-ize`、`-our/-or`、
`-tre/-ter`）。**刻意没有加"双写 l 简化"规则**——那条会把 `filled` 判成 `filed`
的等价形式，属于误判。规则判不对的一律记错，不做模糊匹配。

### 5.5 掌握度分档（`lib/mastery.js`）

```
未测     做过 0 题
薄弱     最近一次答错，或整体正确率 < 50%
待巩固   做对过但还不够稳
已掌握   做过 ≥3 题 且 连对 ≥3 次
```

模考交卷和练习答题都走同一个函数，保证两边口径一致。

### 5.6 错题本（`lib/wrongbook.js`，54 行，PRD §5.7）

**错题在判分时就落库，不等 AI。** AI 之后只往 `error_analysis` 和 `memory_point`
两个字段补内容，所以 AI 不可用时错题本照常能用。

订正规则：`CORRECT_STREAK_TO_CLEAR = 2`，连续答对两次标记已订正；再答错退回未订正
并重新计数。

### 5.7 AI 调用（`lib/ai.js` + `lib/tutor.js`）

四类教学调用：作文批改、错因分析、答案讲解、能力评估。全部走 `chatJSON`（内部带
JSON 强约束，解析失败自动重试一次）。

**最重要的一条实测结论**（PRD §10.0）：Qwen3-8B 是推理模型，不显式关闭思考模式时，
约 2/3 的结构化请求会把 token 全花在内部推理上、返回空对象，延迟从 3 秒涨到 15 秒
以上。所以所有教学调用强制带 `enable_thinking: false`。本地 AI 替身会校验这个字段，
把实测结论变成可执行的检查。

作文批改：五个维度各 0–6 分，按权重合成 30 分制：

```
content 0.30 + language 0.25 + vocabulary 0.15 + coherence 0.20 + length 0.10
```

**分层原则（PRD §10.3）**：AI 只增强体验，主链路不依赖 AI。交卷时不批改，客观题
成绩先出；之后单独调 `/api/ai/attempts/:id/run` 补上。错题分析并发上限
`WRONG_ANALYZE_CONCURRENCY = 5`（为什么是并发而不是串行，见 §9.2）。

### 5.8 API Key 加密（`lib/crypto.js`，41 行）

Web Crypto AES-GCM，密钥来自 Worker secret `ENCRYPTION_KEY`。明文 Key 只在服务端
内存中短暂存在，**绝不下发前端**，读出来一律脱敏成 `sk-****3456`。测试里有一条专门
断言"响应中不含明文 Key"。

`ENCRYPTION_KEY` 一旦轮换，已存的密文就解不开了，所以流水线只在它缺失时才生成。

## 6. 前端结构

`web/src/` 约 1063 行框架 + 2691 行页面。


学员页：`Login`、`UserHome`、`ExamNew`、`ExamTake`、`ExamReport`、`History`、

**响应式约定**：手机 <640px、平板 640–1023px、PC ≥1024px；触控目标 44px；输入框

两处浏览器实测发现的真问题（不是靠读代码发现的）：

## 8. 部署与线上验证

### 8.1 为什么部署走 GitHub Actions

开发沙箱的出站策略拒绝 `api.cloudflare.com`、`workers.dev`、`api.siliconflow.cn`。
所以部署、线上验证、真实 AI 调用一律由 Actions 的运行器代劳，本机 curl 不到线上，
**只能看流水线日志判断线上状态**。

### 8.2 流水线

| 流水线 | 触发 | 作用 |
|---|---|---|
| `deploy-worker.yml` | 推送到开发分支 / 手动 | 22 步全自动部署 |
| `prod-e2e.yml` | **只手动** | 线上端到端实测，会真的花钱调 AI |
| `ai-smoke-test.yml` | 手动 / 推送 | 探测 AI 供应商协议与模型行为 |

`deploy-worker.yml` 的步骤顺序（顺序本身是踩坑改出来的，见 §9.1）：

```
解析账号 → 确保 workers.dev 子域名 → 创建/复用 D1 → 指向数据库
  → 执行迁移 → 部署 Worker → 写入密钥 → 导入题库 → 放行题库
  → 等待响应 → 初始化超级管理员 → 清登录锁定 → 取管理员令牌
  → 初始化学员账号 → 配置 AI → 线上验证 → 输出汇总
```

### 8.3 线上验证里的写入哨兵

线上验证有 18 条断言，其中一条特别重要：

```
OK   写入已恢复（AI 配置 N 秒前刚落库）
```

**D1 写配额耗尽时，所有读接口都正常，只有写会失败。** 所以其余十几条读类断言全绿
也说明不了站点能用。登录以前能当哨兵（它要写最后登录时间），但登录改成"配额耗尽
也放行"之后这个信号就消失了——于是补了这条：读 AI 配置的 `updated_at`，看离现在
多久。AI 配置每次部署都重写，配额耗尽时会回退成沿用旧值，时间戳就会停在上一次
成功部署。

### 8.4 需要的 Secrets 与 Variables

| 名称 | 类型 | 用途 |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | Secret | 需含 **D1:Edit** 权限 |
| `CLOUDFLARE_ACCOUNT_ID` | Secret | 账号 ID |
| `ADMIN_PASSWORD` 或 `ADMIN_PASS` | Secret | 超级管理员密码（两个名字都认） |
| `STUDENT_PASSWORD` | Secret | 学员账号 T001–T010 的初始密码 |
| `SILICONFLOW_API_KEY` | Secret | AI 供应商 Key |
| `AI_BASE_URL` | Variable | 默认 `https://api.siliconflow.cn/v1` |
| `AI_TUTORING_MODEL` | Variable | 默认 `Qwen/Qwen3-8B` |
| `AI_PARSING_MODEL` | Variable | 默认 `deepseek-ai/DeepSeek-OCR` |

流水线自动生成并写入的 Worker Secrets：`JWT_SECRET`、`ENCRYPTION_KEY`（只在缺失时
生成）、`SETUP_TOKEN`（每次轮换）。

## 9. 最贵的四个坑

完整清单和现场记录在 `docs/开发踩坑记录.md`。这里只放代价最大的四个，它们各自
代表一类问题。

### 9.1 D1 每日写入配额耗尽，整站不可用

**现象**：登录返回 500，后来改成 503。

**根因链**：流水线每次部署无条件重导整套题库（约 5700 行写入）→ 免费版每天 10 万
行 → 十几次部署就到顶 → 到顶后所有写操作失败，**包括登录时更新最后登录时间**。

诊断本身被挡了两次：第一次日志尾部被 `request.cf` 的输出占满；第二次 Actions 回显
了 45 行内联 shell 把日志尾部撑爆。**把 shell 挪进 `scripts/ci/*.sh` 之后才看到
真正的错误。**

**三处改动**：

1. **内容指纹必须和数据同批入库。** 修了无条件重导之后踩了个更隐蔽的：导入分两步
   ——先导数据，再单发一条 INSERT 记指纹。第一步成功、第二步撞配额，结果**数据进去
   了、指纹没记上**，下次部署原样重导、再死在同一处，每跑一次白烧 578 行，永远走不
   出来。改成由 `build-seed-sql.mjs` 把指纹写成种子文件的**最后一条语句**，
   `d1 execute --file` 是一次导入，数据和指纹同生共死。

2. **部署排在数据装载之前。** 导入一失败后面的部署整步跳过，**连续八次运行的 Worker
   代码一行都没上线**——而这些改动里可能正好有修复问题的那个。

3. **配额耗尽的降级方向是"写不进"而不是"打不开"。** 登录成功后那两条记账写入（清
   失败计数、更新最后登录时间）改成尽力而为，只吞配额这一类错误。密码已经验过了，
   记账写不进去不该把人挡在门外。

### 9.2 串行调用导致请求超时（替身测不出来）

**现象**：线上实测 `POST /api/ai/attempts/:id/run` 60 秒无任何返回；但同时错题本里
已经有 13 条带上了 AI 错因——**服务端一直在干活，只是客户端等不到。**

**根因**：接口先批改作文、再逐条分析错题，全串行。真实模型一次调用 3–4 秒，错题最
多 20 条，整个请求 80 秒以上。替身瞬间返回，串行毫无问题。

**改法**：`lib/ai.js` 加 `mapLimit`，并发上限 5。20 条分四批约 15 秒，实测整段从
超时变成 30 秒。上限取 5 是为了压总时长的同时不打爆供应商速率限制。

### 9.3 返回结构不符导致静默 0 分（替身测不出来）

**现象**：作文状态"批改成功"，分数 0，而那段作文是通顺的英文。

**根因**：取维度分只认顶层五个数字键，`Number()` 取不到就一律回落 0。真实模型返回
的 JSON 合法但键名不是这套，五个维度全落空，合成出 0 分、状态还标成功。**学生看到
的是一个理直气壮的零分，没人知道是我们没读懂模型的回复。**

**改法**：取分宽容一点（顶层没有就往 `scores`/`result` 等常见嵌套里找，`"5.5分"`
这类字符串也认）；更要紧的是**不再静默兜底**——一个维度都读不到就抛 `ai_bad_shape`，
错误信息带上模型实际返回的顶层键名。真的 0 分和读不到 0 分必须分得开。

### 9.4 测试测的不是它以为的东西（返工六次）

这是单一最大的时间浪费。六种形态都在 `docs/开发踩坑记录.md` §1，这里只举最典型的：

断言"那道错题在两轮专项里都被答对"，期望 2 实际 1。原因是测试挑了错题表里的第一
道，而专项练习按"历史做过次数"升序出题、那道题所属考点下有几十道题，40 轮的循环
根本轮不到它。**测出来的是题库深度，不是订正规则。**

改法：挑"所属考点题目最少"的那道错题，并把选中考点的题量打印出来，下次再红能一眼
分辨是逻辑问题还是数据不够。

由这六次提炼出的通用规则已经沉淀成 `dev-standards` 技能的第一章。

## 10. 从零复现

### 10.1 前提

- GitHub 账号（仓库 + Actions）
- Cloudflare 账号（免费档即可）
- 硅基流动账号（或任何 OpenAI 兼容的供应商）
- Node.js 22+

### 10.2 步骤

**① 取代码**

```bash
git clone https://github.com/tonychenf/Eng1300.git
cd Eng1300
npm install --prefix worker
npm install --prefix web
```

**② 准备 Cloudflare 凭据**

在 Cloudflare 后台建一个 API Token（模板选 "Edit Cloudflare Workers"，**必须额外
添加 Account / D1 / Edit 权限**，否则流水线读不到数据库列表）。记下 Account ID。

**③ 配 GitHub Secrets 与 Variables**

按 §8.4 的表填。`ADMIN_PASSWORD` 和 `STUDENT_PASSWORD` 自己定，至少 8 位且含字母
和数字。

**④ 改掉写死的标识**

以下几处带了本项目的具体值，复现时要改：

| 位置 | 改成 |
|---|---|
| `worker/wrangler.toml` 的 `name` | 你的 Worker 名 |
| `worker/wrangler.toml` 的 `database_id` | 留空也行，流水线会自动创建并回填 |
| `.github/workflows/deploy-worker.yml` 的 `WORKER_NAME`/`D1_NAME` | 同上 |
| 三个流水线的 `branches:` | 你的开发分支名 |
| `.github/workflows/prod-e2e.yml` 的 `WORKER_URL` | 首次部署后由流水线输出 |

**⑤ 推送，等流水线**

推到配好的分支，`deploy-worker.yml` 会自动跑完 22 步并在日志末尾输出公网地址。
第一次运行会创建 D1、建表、导入全部题库（约 5700 行写入，在每日 10 万行额度内）。

**⑥ 验证**

看流水线末尾的"线上验证"一节，18 条应全 OK，其中必须包含
`写入已恢复（AI 配置 N 秒前刚落库）`。

**⑦ 真实 AI 链路实测（会花钱）**

手动触发 `prod-e2e.yml`。它用探针账号 `PROBE01` 走完整条链路，15 条断言。
这一步不能跳——本地替身证明不了真实模型的返回形状扛不扛得住解析。

**⑧ 本地开发**

```bash
cd worker && npx wrangler dev --local --port 8787
```

`wrangler dev` 在受限网络下启动要 100 秒以上（它要连几个被拒的 cloudflare.com
地址、重试到超时）。测试脚本的就绪等待是 150 秒，**不要改短**。

### 10.3 加一套新真题

1. 按 `data/PARSING_GUIDE.md` 的 schema 产出 `data/exams/<courseCode>-<年>-<月>.json`；
   不确定的地方**必须**写进 `parsingNotes`，写明题号。
2. `node scripts/build-seed-sql.mjs` 重新生成种子。
3. 推送。流水线只导入指纹变过的文件，稳态零题库写入。
4. 后台校对页逐条处理存疑记录，然后"发布整卷"。

## 11. 注意事项与运维

### 11.1 D1 免费配额

每天 10 万行写入，**世界时零点（北京时间早八点）重置**。

- 稳态部署零题库写入（靠指纹跳过）。一次完整重导约 5700 行。
- 十个学员各考几次远远够用。
- 配额耗尽时站点退化成"写不进新数据"而不是"打不开"：登录、查看已有记录照常；
  组卷、交卷、练习作答返回 503 并说明恢复时间。
- 排查看 `wrangler d1 execute` 每次打印的 `rows_read` / `rows_written`。

### 11.2 AI 成本

一次完整的"生成 AI 解析"约 21 次模型调用（1 次作文 + 最多 20 条错题）。`prod-e2e`
每跑一次就是这个量。`ai_usage_logs` 表记录每次调用的 token 与延迟，后台有用量页。

### 11.3 安全

- **仓库是公开的。** 线上凭据只进 GitHub Secrets 和 Worker Secrets，绝不写进任何
  提交的文件。
- AI Key 在 D1 里加密存储，读出来一律脱敏，明文不进前端。
- 登录连错 5 次锁 10 分钟。流水线在登录前会先清一次 `login_attempts`；
  `ADMIN_PASSWORD` 和 `ADMIN_PASS` 两个名字都认，但**每个只试一次、不重试**，免得
  把 5 次额度烧光。
- `ENCRYPTION_KEY` 不能轮换，否则已存的 API Key 密文解不开。

### 11.4 探针账号

`PROBE01` 是 `prod-e2e` 用的测试账号，每次跑之前用管理员接口重置密码取随机口令
（所以不必存任何 Secret），它的作答记录不是真学员数据，**看学情看板时要忽略它**。
