# 跨学科自适应学习平台 — 需求文档 v2.0

> 本文档描述的是一个**新项目**：以现有 Eng1300（自考英语真题练习系统）为蓝本复制改造，
> 加入学科层，独立部署、独立数据库、独立域名，与 Eng1300 线上站点零共享。
>
> 平台暂定名 **跨学科自适应学习平台**，代号 `XLearn`（名称待确认，见 §16）。

| 项 | 值 |
|---|---|
| 文档状态 | v2.0，待评审 |
| 蓝本 | Eng1300 `85cbab2`（20 张表 · 50 个接口 · 9561 行代码 · 240 条测试断言） |
| 首个学科 | 英语（自考英语二/专升本），由蓝本迁入 |
| **第二学科** | **生物化学与分子生物学**（已确定） |
| 改造性质 | 在现有功能模块之上**加一层学科架构**，不推翻既有算法与设计 |

## v1 → v2 修订说明

v1 写作时第二个学科未定，架构是按"再来一个和英语结构相似的学科"推演的。
拿到生物化学与分子生物学的例题（《蛋白质的化学》章节习题集）之后，**发现这个假设不成立**，
本版据此做了实质性修订：

| # | v1 的说法 | v2 的修订 | 依据 |
|---|---|---|---|
| 1 | 第二学科待定 | **定为生物化学与分子生物学**，并据其实际形态重排优先级 | 用户确认 |
| 2 | 学科的内容组织都是"年份真题 → 篇章" | **内容组织维度按学科声明**：英语按年份试卷，生化按**教材章节** | 附件是《蛋白质的化学》章节习题集，无年月 |
| 3 | 题库导入管线只是"换提示词" | **整条管线按学科可插拔**：英语是 PDF→OCR→LLM，生化是 **docx→结构化提取** | 附件是数字 docx，走 OCR 反而更差 |
| 4 | 填空题一题一空 | **新增"一题多空"为一等概念**，含数据模型、判分、掌握度、错题本四处改造 | 附件 12 道填空题共 **50 个空**，最多一题 10 个空 |
| 5 | "只有满分或零分"是跨学科铁律 | **降为英语的学科配置**；生化必须支持**按空给部分分** | 一题 10 个空不可能全有全无 |
| 6 | 主观题评分 = 维度加权（作文五维） | **新增第二种 rubric 类型：采分点命中式**，用于名词解释与问答题 | 附件有名词解释 7 条、问答题 2 条 |
| 7 | 题库自带答案 | **新增"缺答案"状态与答案补全工作流** | **附件只有题目，没有答案也没有解析** |
| 8 | 解析存疑 = 解析错了 | **区分"解析存疑"与"原题有误"两种状态** | 附件第 9 题选项标号 D 重复，是原始资料本身的错 |
| 9 | 选项数固定 4 个是个约束 | **撤回**。蓝本已支持 3/4/5/6/7/12 个选项，不是问题 | 实测题库选项数分布 |

**v1 的三个核心架构决策（二级模型、授权不进 JWT、学科码从路径取）经复核仍然成立，
本版未改。**

## 1. 背景与目标

### 1.1 从哪里来：蓝本现状盘点

Eng1300 是一个**已经跑通并上线**的单学科系统，M1–M6 全部完成，线上端到端实测
15 条断言全过。

| 能力 | 现状 |
|---|---|
| 题库 | 20 套自考英语真题 · 1020 道题 · 21 个考点标签 · 895 道可参与组卷 |
| 模拟考试 | 按七部分模板随机组卷、150 分钟限时、交卷即出客观题成绩 |
| 专项练习 | 三阶段自适应（摸底 / 强化 / 单考点），逐题即时反馈 |
| 错题本 | 判分时自动收录，连续答对两次自动订正 |
| 能力评估 | 统计层（时间衰减加权预测）+ AI 定性层，并列呈现 |
| AI 教学 | 作文批改、错因分析、答案讲解、能力评估四类调用 |
| 后台 | 题库校对发布、账号管理、学情看板、数据导出、AI 配置、系统参数 |
| 技术栈 | Cloudflare Workers + D1 + Hono / React 18 + Vite，单域名同时托管前后端 |
| 成本 | 全部落在 Cloudflare 免费额度内 |

**这套东西的产品逻辑与学科无关。** 组卷要考点多样化、练习要按掌握度加权、错题要连对
两次才算订正、AI 不可用时主链路不能塌——这些规则换成生物化学同样成立。

**但它的实现处处是英语。** 判分器里是 29 组英美拼写对照表，AI 提示词里写死"自考英语
科目的阅卷老师"，作文评分维度是"内容/语言/词汇/连贯/字数"，抽题单位是"阅读篇章"。

**这就是本次改造的全部工作量所在**：把"与学科无关的系统能力"和"某个学科特有的知识"
拆开，前者共享，后者下沉到学科自己的配置里。

### 1.2 要做成什么

一句话：**把 Eng1300 从"一门课的练习系统"改造成"一个能装下任意学科的学习平台"，
每个学科有自己的题库、解析和评价标准，共用同一套系统能力，账号跨学科统一、权限按
学科授予。**

| # | 要求 | 本文档对应章节 |
|---|---|---|
| 1 | 跨学科学习平台，新增学科选择功能 | §3 架构决策、§6.3 学科选择与切换 |
| 2 | 不同学科独立题库 | §6.4 |
| 3 | 不同学科独立例题解析 | §6.5 |
| 4 | 不同学科独立评价标准 | §6.6 |
| 5 | 学科共享系统功能与设计思路 | §3.4、§5 学科能力包、§6.7 |
| 6 | 同一账号下按学科授权，权限由管理员设置 | §6.2、§7 权限矩阵 |
| 7 | 所有报告按学科区分 | §6.8 |
| 8 | 独立部署 | §11 |

### 1.3 本期范围（In Scope）

- 学科作为一等公民：建模、管理、选择、切换、隔离
- 学科级访问权限：授予、撤销、有效期、审计
- 学科能力包：题型、考点体系、内容组织维度、导入管线、判分规则、解析规格、
  评价标准全部可按学科配置
- 现有七大功能模块（模考、练习、错题本、能力评估、历史记录、学情看板、数据导出）
  全部加上学科维度
- **英语**作为第一个学科完整迁入，行为与现状一致
- **生物化学与分子生物学**作为第二个学科完整跑通，含一题多空判分与采分点式主观题评分
- 独立部署流水线与独立数据库

### 1.4 明确不做（Out of Scope）

| 不做 | 理由 |
|---|---|
| 学科之间的知识迁移分析、跨学科推荐算法 | 属于下一阶段，本期只做跨学科**数据汇总**（§6.9） |
| 学员自助注册、自助申请开通学科 | 权限明确要求"由管理员设置"，先做管理员授予 |
| 多租户（多个互不可见的机构） | 当前是单机构多学科，没有需求支撑 |
| 移动 App | 沿用蓝本决策，只做响应式网页 |
| 付费/订阅 | 沿用蓝本约束：完全免费 |
| 题目的在线富文本编辑器 | 题库仍走"数据文件 → 种子 → 导入"管线，后台只做校对、补答案与发布 |
| 学科间的题目复用 | 题目归属唯一学科，不做跨学科挂载 |
| **化学结构式 / 分子式图形编辑器** | 生化题面用文本 + 上下标 + 希腊字母即可覆盖附件全部内容，图形编辑器不在本期 |
| **手写公式识别** | 同上 |

### 1.5 成功判据

**生物化学与分子生物学学科完整上线，且上线过程中对"英语"相关的任何代码零改动；
英语学科的 240 条断言全部仍然通过。**

v1 把成功判据写成"新增学科零代码"。拿到生化例题后这条要修正：**生化确实需要写代码**
——它需要一个归一化器、一个采分点判分器、一个 docx 导入器。零代码的说法过于乐观。

修正后的判据分两级：

| 级别 | 判据 |
|---|---|
| **硬指标** | 生化上线不改动任何英语专属代码，英语行为零漂移 |
| **软指标** | 生化新增的代码全部落在 `worker/src/subjects/biochem/` 与 `scripts/ingest/docx/` 两个目录内，系统骨架（组卷、练习、错题、评估、报告）零改动 |

达不到软指标，说明学科层没抽干净，第三个学科还会再痛一次。

## 2. 名词定义

在蓝本 `docs/prd.md` §2 的基础上新增和修订：

| 名词 | 定义 | 是否新增 |
|---|---|---|
| **学科（Subject）** | 平台的顶层分区，如"英语""生物化学与分子生物学"。**学科是权限边界、数据隔离边界和报告边界** | 🆕 |
| **学科能力包（Subject Pack）** | 一个学科跑起来所需要的全部配置与知识。见 §5 | 🆕 |
| 课程（Course） | 学科下的一门具体科目。**课程决定组卷模板和试卷规格**，一个学科可有多门课程 | 修订：从顶层降为学科的下级 |
| **内容组（ContentGroup）** | 题目的组织单元。英语里它是"一套年份真题"，生化里它是"一个教材章节"。对应蓝本的 `exams` 表 | 🆕（泛化自"真题"） |
| **题组（Section）** | 内容组内的一个分组。英语里是"一篇短文 + 若干小题"，生化里是"一个题型分组（填空/选择/名词解释/问答）" | 修订：从"部分"泛化 |
| 题目（Question） | 最小作答单位 | 不变 |
| **空（Blank）** | 一道填空题内的一个独立填写位与其独立得分。**一道题可以有多个空** | 🆕 |
| 考点（KnowledgePoint） | 题目考查的知识点标签，支持两级（章 → 知识点） | 修订：**从全局共用改为按学科独立**，并支持分层 |
| **例题解析（Explanation）** | 一道题的结构化解题说明。结构由学科定义，来源可以是原卷官方解析、人工录入或 AI 生成 | 🆕 |
| **例题（Exemplar）** | 学科自建的典型题目 + 完整解题过程，用于教学讲解，**不进入组卷与练习抽题池** | 🆕 |
| **评价标准（Rubric）** | 一个学科怎么算对错、怎么给分、怎么判掌握、怎么预测成绩的全部参数 | 🆕 |
| **采分点（ScorePoint）** | 主观题答案里的一个得分要点。命中即得该点的分 | 🆕 |
| 模考（Exam Attempt） | 按试卷规格组卷、限时的一次完整测验 | 不变 |
| 练习（Practice Session） | 不限时、逐题反馈的一次训练 | 不变 |
| 掌握度（Mastery） | 用户在某个考点上的累计表现档案 | 修订：键加入 `subject_id` |
| **学科授权（Subject Grant）** | 管理员授予某账号访问某学科的权限记录 | 🆕 |

## 3. 架构决策：学科放在哪一层

### 3.1 现状：蓝本已经有半层隔离

盘点蓝本代码可以发现一件重要的事：**`course_code` 已经贯穿了大部分表**。

| 表 | 是否已有 `course_code` |
|---|---|
| `exams` / `questions` / `exam_templates` | ✅ 有 |
| `attempts` / `user_knowledge_mastery` / `wrong_items` / `assessments` | ✅ 有 |
| `sections` | ❌ 无（通过 `exam_id` 间接关联） |
| `knowledge_points` / `question_knowledge_points` | ❌ **无，全局共用** |
| `system_settings` / `ai_settings` | ❌ **无，全局单例** |
| `users` | ❌ 无（角色只有 `SUPER_ADMIN` / `USER`） |

题库和学情数据的隔离骨架已经在了，缺的是：

1. 一个真正的顶层概念
2. 考点体系、系统参数、AI 配置的隔离（现在是全局的，两个学科会互相污染）
3. 权限维度
4. 报告的学科过滤（后台学情看板**当前完全没有按课程过滤**，见 §6.8）

这个现状决定了改造是**加一层**而不是**推倒重来**——正是用户的原话："相当于这些
功能模块儿，在上面添加一层学科的架构"。

### 3.2 三种候选方案

**方案 A：学科即课程（把 `courses` 改名成 `subjects`）**

改动最小，但一个学科下确实会有多门规格不同的课程。按方案 A，它们只能是两个学科，
于是考点要建两套、权限要发两次、报告要分两张——恰恰是本次改造要消灭的重复。**否决**。

**方案 B：学科 → 课程 二级模型（推荐）**

- `subjects` 为新顶层表，`courses` 增加 `subject_id` 外键
- **学科**承载：权限、考点体系、内容组织维度、导入管线、解析规格、评价标准、
  AI 提示词、参数覆盖、报告边界
- **课程**承载：组卷模板、试卷规格（时长、满分、题量分值）、题库归属

**方案 C：学科 → 课程 → 模块 三级** —— 没有需求支撑，**否决**。

### 3.3 决定：采用方案 B

```
学科 Subject（权限边界 · 报告边界 · 知识体系边界）
  │  subject_id, code, name, status, 能力包配置
  │
  ├─ 考点体系 knowledge_points（按学科独立，支持两级）
  ├─ 评价标准 subject_rubrics（判分 / 主观题 / 掌握度 / 能力评估）
  ├─ 解析规格 subject_explanation_schema
  ├─ AI 提示词 subject_ai_prompts
  ├─ 参数覆盖 subject_settings（覆盖全局 system_settings）
  ├─ 内容组织维度 content_group_kind（EXAM_PAPER / TEXTBOOK_CHAPTER）
  ├─ 导入管线 ingest_pipeline（pdf-ocr-llm / docx-structured / json-direct）
  │
  └─ 课程 Course（试卷规格边界）
       │  course_code, subject_id, 时长, 满分
       ├─ 组卷模板 exam_templates
       └─ 内容组 ContentGroup（英语=年份真题 / 生化=教材章节）
            └─ 题组 Section（英语=篇章 / 生化=题型分组）
                 └─ 题目 Question ─┬─ 空 Blank（一题多空）
                                   └─ 例题解析 Explanation
```

**学情数据的键**：`attempts` / `wrong_items` / `assessments` / `user_knowledge_mastery`
同时冗余存 `subject_id` 和 `course_code`。

为什么冗余而不是只存 `course_code` 再 join：

- 学科级报告是最高频查询（每次进错题本、能力评估、历史记录都要按学科过滤）
- 现有索引是按 `course_code` 建的（如 `idx_wrong_user ON wrong_items(user_id, course_code, corrected)`），
  每次都 join 意味着索引要重建且多一跳
- 风险是两列不一致，用外键 + **写入统一走同一个函数**兜住，不允许调用方自己拼 `subject_id`

## 4. 第二学科画像：生物化学与分子生物学

**本章是 v2 的核心新增内容。** 它把"第二个学科长什么样"从假设变成事实——所有结论
都来自用户提供的《蛋白质的化学》章节习题集（.docx），逐条可核对。

**为什么要专门写一章**：架构抽象最怕的是"按想象中的第二个学科去抽"。真实的第二个
学科一旦和想象不一样，抽出来的接缝就全错位。这一章的作用是**用真实资料逼出真实需求**。

### 4.1 资料形态

| 项 | 实测值 |
|---|---|
| 文件 | 一个 `.docx`（Word 2007+），20,032 字节 |
| 标题 | 《蛋白质的化学》—— **一个教材章节，不是一份年份试卷** |
| 题量 | 35 道（填空 12 + 选择 14 + 名词解释 7 + 问答 2） |
| **答案** | **没有** |
| **解析** | **没有** |
| 文字层 | 完整数字文本，**不需要 OCR** |

**原始 docx 不进仓库。** 沿用蓝本对真题 PDF 的处理（`docs/项目全档.md` §3.1：
"原始 PDF 没有进仓库，体积大且有版权顾虑"）——仓库是公开的，教材习题有版权顾虑。
本章记录的是**从附件读出的结构性事实**，导入器的样本文件另行以私有方式提供给开发者。
这意味着 §14.3 的 B1～B4 是**本地验收项**，不进 CI。

### 4.2 从附件读出的九条事实

每一条都附了证据，改造时可以拿原件核。

#### 事实 1：内容组织是"教材章节"，不是"年份真题"

标题《蛋白质的化学》是生化教材的一章。生化与分子生物学教材通常 20～25 章
（蛋白质、核酸、酶、糖代谢、脂代谢、氨基酸代谢、生物氧化、DNA 复制、转录、翻译、
基因表达调控……），学员的学习路径是**按章推进**，而不是按年份刷卷。

**影响**：蓝本 `exams` 表的 `year INTEGER NOT NULL, month INTEGER NOT NULL` 对生化
无意义且**无法填写**。必须放宽为可空，并新增内容组类型字段。

#### 事实 2：一道填空题有多个空，最多 10 个

实测 12 道填空题共 **50 个空**，平均 **4.2 空/题**：

| 题号 | 空数 | 题干节选 |
|---|---|---|
| 2 | **10** | 组成蛋白质的元素有 ＿、＿、＿、＿、＿、＿ 等，有些蛋白质还含有金属元素如 ＿、＿、＿、＿ 等 |
| 3 | 6 | 肽键包含 ＿、＿、＿、＿ 以及与之相连的 2 个 ＿ 原子，这 6 个原子位于同一平面，该平面称为 ＿ |
| 5 | 5 | 碱性氨基酸有 ＿、＿ 和 ＿。其等电点 ＿（高/低）于生理 pH，该氨基酸残基带 ＿（正/负）电 |
| 9 | 5 | 蛋白质的二级结构形式有 ＿、＿、＿ 和 ＿ 等。维持其稳定的主要化学键是 ＿ |

**影响**：这是 v2 最大的一处架构修订。蓝本的 `questions.answer` 是**单个文本字段**，
`grade.js` 的判分是 `canonWord(答案) === canonWord(标准答案)` 的**单值比较**。
一题 10 个空根本装不进去。详见 §6.4.5。

#### 事实 3：必须有部分分

一道 10 个空的题，学生答对 7 个。按蓝本的"只有满分或零分"规则记 0 分，
**既不合理也不可能被接受**。

**影响**：蓝本 `docs/prd.md` §4.3 的"不给部分分"是**英语完形填空的官方评分参考**，
不是跨学科铁律。v1 把它写成了共享约束，v2 修正为**学科配置**。

#### 事实 4：有三种不同语义的空

| 语义 | 证据 | 判分要求 |
|---|---|---|
| **无序并列** | "酸性氨基酸有 ＿ 和 ＿"（天冬氨酸/谷氨酸，顺序无关）；"组成蛋白质的元素有 ＿、＿、＿、＿、＿、＿" | **集合比对**，不能逐空按位置比 |
| **受限选择** | "其等电点 ＿（高/低）于生理 pH"、"带 ＿（正/负）电" | 答案只能取题干括号里给出的枚举值 |
| **数值** | "该元素约占蛋白质质量的 ＿%"（16）、"最大吸收峰波长是 ＿ nm"（280） | 数值容差比较 |

**影响**：空需要有 `blank_kind` 字段，判分按语义分派。**无序并列是硬需求**——
按位置逐空比对会把"谷氨酸、天冬氨酸"判成全错。

#### 事实 5：同一概念有中文名、三字母缩写、单字母三种写法

附件内部就不统一：

- 选择题第 2 题选项是 `Pro / Lys / His / Glu`（三字母缩写）
- 选择题第 3 题选项是 `赖氨酸 / 蛋氨酸 / 亮氨酸 / 谷氨酸`（中文名）

**影响**：生化归一化器必须维护**氨基酸等价表**（中文名 ↔ 三字母 ↔ 单字母），
否则学生填 `Cys` 而标准答案是 `半胱氨酸` 会被判错。规格见 §5.4。

#### 事实 6：大量希腊字母、上下标与特殊符号

实测出现：`α-螺旋`、`β-折叠`、`β-巯基乙醇`、`-S-S-`、`L-型` / `D-型`、`pH`、
`280nm`、`motif`。

**影响**：

- 题干与选项渲染要支持这些字符（纯文本即可，不需要公式引擎）
- 归一化器要处理全角/半角、希腊字母的中文写法（"α" vs "阿尔法"）、
  连字符变体（`-` / `－` / `—`）

#### 事实 7：Word 自动编号导致题号与选项字母不在文本里

这是**导入管线的头号陷阱**，naive 文本提取会静默产出错数据：

| 现象 | 证据 |
|---|---|
| 填空题**编号方式不统一** | 第 1、3–10、12 题题号手打在文本里；**第 2、11 题用 Word 自动编号，文本里没有题号** |
| 手打题号标点也不统一 | `1．`（全角句点）、`3.`（半角）、`6. `（半角+空格）、`10．`（全角） |
| 选择题**题号全部来自自动编号** | 14 道题的文本里一个题号都没有 |
| 选项 **A 的字母来自自动编号** | 提取出的选项行长这样：`丙氨酸    B.亮氨酸    C.甘氨酸    D.丝氨酸` —— **A 不见了** |
| 第 13 题的 5 个选项是 5 个独立段落 | 字母全部来自自动编号，文本里一个字母都没有 |
| 第 14 题又是另一种写法 | 选项行**没有**自动编号，文本里 `A.8.0  B.7.0  C. 6.0  D.5.0  E.4.0` 齐全 |

**影响**：导入器必须解析 `word/numbering.xml` 还原自动编号，而不是只取 `<w:t>` 文本。
**并且必须容忍同一份文件里三种编号约定并存**。这正是蓝本处理 OCR 不一致换行时的
同类问题——`docs/项目全档.md` §3.1 写过"提示词必须容忍 OCR 产生的不一致换行"。

#### 事实 8：原始资料本身有错

选择题第 9 题的选项标号：

```
三级结构     D.缔合现象     C.四级结构     D.变构现象
              ↑ 应为 B                      ↑ D 重复
```

**影响**：蓝本的 `exam_parsing_notes` 存疑机制假设"错误来自解析"。这里错误来自
**原始资料**。两者的处理方式不同：解析存疑要重新解析，原题有误要人工订正原文。
必须分成两种状态，见 §6.4.6。

#### 事实 9：题干可能跨段落

第 7 题的题干在 docx 里是两个段落：`…蛋白质的最大吸收峰波长是` + `nm。`

**影响**：导入器不能假设"一段 = 一题"，需要按题号边界合并段落。

### 4.3 与英语的结构性差异对照

| 维度 | 英语（蓝本） | 生物化学与分子生物学 |
|---|---|---|
| 内容组织 | 年份真题试卷（20 套） | **教材章节**（约 20～25 章） |
| 题组语义 | 一篇短文 + 若干小题 | **一个题型分组** |
| 抽题单位 | **篇章级**（拆开就没语境） | **单题级**（题目互相独立） |
| 题型 | 单选、词形变换填空、写作 | **填空（多空）、单选、名词解释、问答** |
| 填空 | 一题一空，给定词做词形变换 | **一题多空，平均 4.2 空** |
| 部分分 | **不给**（官方评分参考） | **必须给**（按空计分） |
| 主观题评分 | 作文五维加权（内容/语言/词汇/连贯/字数） | **采分点命中式** |
| 判分难点 | 英美拼写等价 | **中文名/三字母/单字母等价、数值容差、无序集合** |
| 原始资料 | 扫描 PDF（无文字层） | **数字 docx（有完整文字层）** |
| 导入管线 | PDF → DeepSeek-OCR → Qwen3-8B → JSON | **docx → 结构化提取（含编号还原）→ JSON** |
| 答案来源 | **真题自带答案与官方解析** | **习题集不带答案，需补** |
| 主要使用模式 | 模考为主（按真题结构组卷） | **章节练习为主**，模考为辅 |

**最后一行值得单独说**：英语学员的目标是"考过那张卷子"，所以按真题结构组卷是核心。
生化学员的目标是"掌握这门课的知识体系"，**按章节做专项练习才是主路径**，模考是阶段性
检验。这意味着生化的组卷模板不是从真题里抽出来的，而是**自己定义的**（见 §6.4.2）。

### 4.4 这些差异对架构提出的九条新要求

逐条对应上面的事实，是 §5～§6 展开的依据：

| # | 要求 | 来自事实 | 展开在 |

| R2 | 一题多空：数据模型、判分、掌握度、错题本四处改造 | 2 | §6.4.5 |

| R4 | 空的三种语义（无序并列 / 受限选择 / 数值）与对应判分器 | 4 | §6.4.5 |
| R5 | 生化归一化器：氨基酸等价表 + 特殊字符 + 数值容差 | 5、6 | §5.4 |
| R6 | 导入管线按学科可插拔，docx 导入器需还原自动编号 | 7、9 | §6.4.3 |

### 5.3 声明式与代码插件的边界

**原则：能用数据表达的一律用数据；只有"语义判断"才允许写代码。**

- **纯数据即可**：题型清单、评分维度与权重、掌握度阈值、考点体系、组卷模板、
  解析结构、AI 提示词、内容组织维度、抽题单位
- **必须写代码**：归一化器（语义等价判断）、导入器（文件格式解析）、
  特殊抽题策略（声明式表达不了时）

生化需要写的代码，全部落在两个目录：

```
worker/src/subjects/biochem/
    normalizer.js        答案归一化（氨基酸等价、希腊字母、数值容差）
    normalizer.test.mjs  等价与**非等价**用例
scripts/ingest/docx/
    extract.js           docx → 结构化中间态（含自动编号还原）
    to-question-json.js  中间态 → 题库 JSON
```

**约束（沿用蓝本铁律）**：归一化器只能做"等价折叠"，不能做"模糊匹配"。
蓝本 `grade.js` 刻意没加"双写 l 简化"规则，因为它会把 `filled` 判成 `filed` 的
等价形式。生化同样：**宁可判错记错，不可把错答放过**。每条等价规则都要有单元测试
给出它不会误判的证明——按 `dev-standards` 的要求，**测试写完要把被测逻辑临时改成
返回常量跑一次，确认变红**。

### 5.4 生化归一化器规格

这是生化唯一必须写的判分代码，规格先定下来：

#### ① 氨基酸等价表

20 种标准氨基酸的三种写法互认：

```
中文名        三字母   单字母
甘氨酸        Gly      G
丙氨酸        Ala      A
半胱氨酸      Cys      C
谷氨酸        Glu      E
天冬氨酸      Asp      D
赖氨酸        Lys      K
精氨酸        Arg      R
组氨酸        His      H
蛋氨酸/甲硫氨酸 Met     M
…（共 20 条）
```

**注意两处别名**：`蛋氨酸` 与 `甲硫氨酸` 是同一个（Met）；`天冬氨酸` 与 `门冬氨酸`
是同一个。这类中文别名必须显式列出，**不允许用"去掉某个字"这种规则去凑**。

#### ② 字符归一化

| 规则 | 例 |
|---|---|
| 全角 → 半角（字母、数字、标点） | `Ａ` → `A`，`％` → `%` |
| 希腊字母的中文写法 → 希腊字母 | `阿尔法` / `alpha` → `α` |
| 连字符变体统一 | `－` / `—` / `‐` → `-` |
| 去除首尾空白与句末标点 | `半胱氨酸。` → `半胱氨酸` |
| 大小写不敏感（拉丁字母部分） | `cys` = `Cys` |

**明确不做**：中文同音字替换、繁简转换、"氨"与"胺"互认。
这三条都会把不同的物质折到一起——`氨基酸` 和 `胺基酸` 在教材里是不同写法但
`谷氨酸` 和 `谷胺酸` 只有一个是对的，折叠会放过错答。

#### ③ 数值比较

| 参数 | 默认 | 说明 |
|---|---|---|
| 相对容差 | 0.5% | `16` 与 `16.0` 与 `16%` 判对 |
| 单位处理 | 剥离后比数值 | `280nm` = `280` = `280 nm` |
| 整数/小数 | 等值即可 | `16` = `16.00` |

单位与数值都要比：`280nm` 与 `280g` 不判对。

#### ④ 集合比较（无序并列空）

学生答案按分隔符（`、` `,` `;` 空格）切分成集合，与标准答案集合比。
**元素两两之间走①②的等价判定**。集合相等才算全对；部分命中按
`命中数 / 应答数 × 该空组总分` 给分（是否给部分分由 rubric 决定）。

### 5.5 新增一个学科的标准流程

1. 后台「学科管理」新建学科，填元信息、内容组织维度、导入管线 → 得到 `subject_id`
2. 准备考点表 `data/subjects/<code>/knowledge-points.json`
3. 声明题型清单与评价标准
4. 按该学科的规范产出题库 JSON `data/subjects/<code>/groups/*.json`
5. 配置组卷模板
6. `node scripts/build-seed-sql.mjs --subject <code>` 生成种子
7. 推送 → 流水线按指纹增量导入
8. 后台校对、**补答案**、发布
9. 管理员给相关账号授予该学科权限
10. 学员登录即可在学科选择页看到并进入

**第 8 步的"补答案"是生化特有的**，英语真题自带答案没有这一步。详见 §6.4.6。

## 6. 功能需求

### 6.1 学科管理（后台 · 新增）

**页面**：`/admin/subjects`（列表）、`/admin/subjects/:id`（详情与配置）

**列表页元素**：学科名称、学科码、状态、课程数、内容组数、已发布题数、
**缺答案题数**、考点数、授权人数、最近更新时间。

**业务规则**：

| 规则 | 说明 |
|---|---|
| 学科码唯一且不可修改 | 它会进 URL、进导出文件名、进种子文件名 |
| 学科码格式 | `^[a-z][a-z0-9-]{1,19}$`，如 `english`、`biochem` |
| 内容组织维度不可改 | 建科时定 `EXAM_PAPER` 或 `TEXTBOOK_CHAPTER`，改了会让已有内容组语义断裂 |
| 停用学科 | 学员侧不可见、不可进入；**已有数据保留不删**，管理员仍可查看与导出 |
| 删除学科 | **本期不提供**。有作答数据后删除会造成报告口径断裂；只允许停用 |
| 学科下无课程 | 允许创建，学员进入时提示"该学科尚未开放内容" |
| 配置变更的生效时点 | 评价标准变更**只对变更后产生的新作答生效**，不回溯重算历史报告 |

**最后一条是硬要求**：评价标准可改，但改了以后老报告分数不能变，否则学员会发现
"上周考了 72 分，今天再看变成 68 分"。实现方式是 `attempts` 记录当次使用的
`rubric_version`，报告按该版本渲染。

**异常处理**：学科码重复 → 409；停用一个学员正在答题的学科 → 允许停用，
但**进行中的作答会话必须能正常交卷**（停用只拦新会话）。

### 6.2 学科访问权限（新增 · 本次改造的重点）

用户要求原文：「同一个账号下，不同学科有独立的访问权限，权限由管理员来设置。」

#### 6.2.1 权限模型

权限 = **全局角色** × **学科授权**，两者都满足才放行。

**全局角色**（扩展蓝本的两值枚举）：

| 角色 | 说明 | 相对蓝本 |
|---|---|---|
| `PLATFORM_ADMIN` | 平台超级管理员。管学科、管账号、管授权、管 AI 配置、看全平台数据 | 由 `SUPER_ADMIN` 改名 |
| `SUBJECT_ADMIN` | 学科管理员。只在被授权的学科内管题库、补答案、看学情 | 🆕 |
| `USER` | 学员 | 不变 |

**学科授权**（新表 `user_subject_grants`）：

| 字段 | 说明 |
|---|---|
| `user_id` + `subject_id` | 联合主键 |
| `access_level` | `STUDENT`（做题） / `MANAGER`（管题库与学情） |
| `status` | `ACTIVE` / `SUSPENDED` |
| `granted_by` / `granted_at` | 谁在什么时候授予的 |
| `expires_at` | 到期时间，可空表示长期有效 |
| `note` | 备注（如"2026 春季班"） |

**判定规则**：

```
PLATFORM_ADMIN            → 所有学科全权限，不需要授权记录
SUBJECT_ADMIN + MANAGER   → 该学科的题库管理 + 学情查看
SUBJECT_ADMIN 无授权记录  → 该学科 403
USER + STUDENT(ACTIVE 且未过期) → 该学科的学员功能
USER 无授权 / SUSPENDED / 已过期 → 该学科 403
```

#### 6.2.2 关键设计决策：学科授权不进 JWT

蓝本的 JWT 带 `role`，有效期 8 小时（`worker/src/lib/auth.js`）。

**如果把学科授权列表塞进 JWT，管理员撤销权限最长要等 8 小时才生效。** 对"权限由管理员
设置"这条需求不可接受——管理员点了撤销，界面说成功了，学员却还能继续做题。

所以：

- JWT 只带 `user_id` + 全局角色（与现状一致，不改签发逻辑）
- **学科授权每次请求查库**：一次命中主键索引的单行查询，D1 上成本可忽略
- 允许在 Worker 实例内存里缓存 ≤ 60 秒，削掉同一次页面加载的重复查询；
  **撤销必须在 60 秒内全网生效**，写进验收标准
- 读操作走缓存，**授权变更与所有写操作一律穿透到库**

#### 6.2.3 强制执行点

| 层 | 措施 |
|---|---|
| 路由 | 所有学科相关接口统一前缀 `/api/s/:subjectCode/...`，学科**从路径取，不从请求体取** |
| 中间件 | 新增 `requireSubjectAccess(level)`，与蓝本 `requireAuth` 同一位置 |
| 查询 | 所有学科数据查询强制带 `subject_id = ?`，且必须先过中间件 |
| 越权响应 | 统一 `403 { error: 'subject_forbidden', message: '你没有该学科的访问权限，请联系管理员开通' }` |
| 学科不存在 | `404`。学科的存在性不是机密 |

**为什么强调"从路径取"**：蓝本现有接口（如 `GET /api/assessment?courseCode=xxx`）
从 query 取课程码，服务端只校验参数存在、不校验归属。多学科之后这条路径就是越权漏洞：
拿 A 学科的 token 传 B 学科的 code 就能读到别人的数据。改成路径参数 + 统一中间件，
是为了让"漏掉校验"变成一件**做不到**的事，而不是靠每个接口自觉。

#### 6.2.4 管理界面

**页面**：`/admin/users/:id/subjects`（单人视角）与 `/admin/subjects/:id/members`（单学科视角）

两个视角都要有：新学员入学要一次给他开好几个学科；新学科开课要一次给一批学员开通。

- 单人视角：列出全部学科，可直接勾选开通/关闭、设置级别与有效期
- 单学科视角：列出已授权成员，支持**批量授予**（粘贴用户名列表或多选）、批量撤销
- 每次变更写 `subject_grant_audit` 审计表
- 授权变更不发通知（本期无通知系统），学员下次进学科选择页即可看到变化

**异常处理**：给不存在的用户名授权 → 明确列出哪几个没找到，其余正常授予，不整批失败。

### 6.3 学科选择与切换（用户端 · 新增）

#### 6.3.1 学科选择页

**路由**：`/app`（登录后的默认落地页）

- 卡片式列出该账号**有权访问且未停用**的学科
- 每张卡片显示：学科名、简介、我的进度摘要（已考次数 / 待订正错题数 / 上次活动时间）
- 无权访问的学科**不展示**（不做"灰色不可点"，避免造成"为什么不给我开"的反复询问）
- 一个学科都没有 → 空状态页："管理员尚未为你开通任何学科，请联系管理员"

**降级规则**（沿用蓝本对课程选择器的处理思路）：**只有一个可访问学科时自动进入，
不显示选择页**，但顶部仍保留学科名标识。判断条件写"可访问学科数 > 1 才显示"，
不硬编码学科码。

#### 6.3.2 学科上下文与切换

- 进入学科后 URL 带学科码：`/app/biochem/practice/new`、`/app/english/wrongbook`
- 前端新增 `SubjectContext`，持有当前学科元信息与能力包（题型、内容组织维度、
  考点树等），页面据此决定渲染什么控件
- 顶部导航常驻**学科切换器**（可访问学科 > 1 时显示）
- 学科选择记忆在 localStorage，下次登录直接落到上次的学科；
  **每次都要重新校验权限**，被撤销时回到选择页并提示
- **答题中不允许切换学科**。答题页本就不套导航外壳（蓝本设计），天然满足；
  但要防住直接改 URL 的情况——切换时若存在进行中的会话，弹确认

#### 6.3.3 导航按学科能力包生成

蓝本的 `USER_NAV` 是写死的数组。改造后按学科生成，例如：

| 导航项 | 英语 | 生化 |
|---|---|---|
| 模拟考试 | ✅ | ✅（模板自定义） |
| 专项练习 | ✅ | ✅ **主路径，排在模考之前** |
| 错题本 | ✅ | ✅ |
| 能力评估 | ✅ | ✅ |
| 例题 | — | ✅ |
| 历史记录 | ✅ | ✅ |

**生化把"专项练习"排在"模拟考试"之前**，因为它的主要使用模式是按章节练习
（§4.3 最后一行）。导航顺序进学科配置，不写死。

### 6.4 独立题库

#### 6.4.1 隔离要求

| 对象 | 隔离方式 |
|---|---|
| 内容组 `exams` | 新增 `subject_id` |
| 题组 `sections` | 新增 `subject_id`（蓝本没有，只能靠 `exam_id` 间接关联） |
| 题目 `questions` | 已有 `course_code`，新增 `subject_id` |
| 空 `question_blanks` 🆕 | 随题目 |
| 考点 `knowledge_points` | **新增 `subject_id`，主键改 `(subject_id, tag_id)`** |
| 组卷模板 `exam_templates` | 已按 `course_code` 隔离，课程归学科 |

**考点是重点**：蓝本的 `knowledge_points.name` 有全局 `UNIQUE` 约束。
英语的"固定搭配"和生化的某个同名考点会撞。改造后降为 `(subject_id, name)` 联合唯一。

**跨学科抽题是禁止的**：组卷、练习、错题本的所有查询必须带 `subject_id`，
绝不允许抽到别的学科的题。这一条要写成测试断言。

#### 6.4.2 内容组织维度按学科（🆕 R1）

蓝本的 `exams` 表假定内容组是"年份真题"：`year INTEGER NOT NULL, month INTEGER NOT NULL`。
生化的内容组是教材章节，**没有年月可填**。

**改造**：

```sql
-- exams 表（语义泛化为"内容组"）
year   INTEGER     NULL,        -- 放宽：章节型内容组为空
month  INTEGER     NULL,        -- 放宽
group_kind  TEXT NOT NULL,      -- 'EXAM_PAPER' | 'TEXTBOOK_CHAPTER'
chapter_no  INTEGER NULL,       -- 🆕 章节序号，章节型必填
```

| 学科 | `group_kind` | 标题示例 | 排序依据 |
|---|---|---|---|
| 英语 | `EXAM_PAPER` | 2026年4月高等教育自学考试英语(专升本)试题 | `year, month` |
| 生化 | `TEXTBOOK_CHAPTER` | 第01章 蛋白质的化学 | `chapter_no` |

**约束**：`group_kind = 'EXAM_PAPER'` 时 `year`/`month` 必填；
`'TEXTBOOK_CHAPTER'` 时 `chapter_no` 必填。用 `CHECK` 约束表达，不靠应用层自觉。

**题组（`sections`）的语义也跟着泛化**：

| 学科 | 题组是什么 | `passage_text` 用途 |
|---|---|---|
| 英语 | 一篇短文 + 若干小题 | 阅读原文 |
| 生化 | 一个题型分组（填空/选择/名词解释/问答） | 空（生化题目互相独立，无共享材料） |

**抽题单位随之不同**：英语是 `SECTION`（拆开就没语境），生化是 `QUESTION`
（题目互相独立）。蓝本 `lib/paper.js` 的候选条件"篇章已发布题量正好等于模板要求"
对生化毫无意义——生化一个题型分组里有 12 道填空题，模板要 20 道，是从**全学科的
填空题池**里抽 20 道，不是抽一个分组。

#### 6.4.3 导入管线按学科可插拔（🆕 R6）

| 学科 | 管线 | 步骤 |
|---|---|---|
| 英语 | `pdf-ocr-llm` | 扫描 PDF → DeepSeek-OCR 转文字 → Qwen3-8B 结构化 → JSON |
| 生化 | **`docx-structured`** | docx → **XML 结构化提取（含自动编号还原）** → 规则切分 → JSON |

**生化不走 OCR 也不走 LLM 结构化**，理由：

- 附件是数字 docx，有完整文字层，OCR 只会引入错误
- 题型边界（填空题/选择题/名词解释/问答题）由标题段落明确标出，规则切分即可
- 走 LLM 反而会引入不确定性，且要花钱

**docx 导入器的硬性要求**（对应 §4.2 事实 7、9）：

1. **必须解析 `word/numbering.xml` 还原自动编号**，不能只取 `<w:t>` 文本。
   否则选择题 14 道题全部丢题号、13 道题的 A 选项全部丢字母。
2. **必须容忍同一份文件里多种编号约定并存**：手打题号（全角/半角/带空格三种标点）、
   自动编号、以及第 14 题那种"选项行无编号但文本里字母齐全"。
3. **必须按题号边界合并跨段落的题干**（第 7 题的 `nm。` 是独立段落）。
4. **提取到的每一道题都要回写"原始段落索引"**，便于人工核对时定位回原文。
5. 拿不准的一律写进 `parsing_notes`，**写明题号**——沿用蓝本
   `data/PARSING_GUIDE.md` §4 的要求。

**验证要求**：导入器跑完附件这一章，必须产出 12 + 14 + 7 + 2 = **35 道题**，
其中填空题 **50 个空**。数量对不上就是导入器有问题，这是可执行的自检。

#### 6.4.4 题型开放

蓝本 `questions.question_type` 的 `CHECK` 约束只认三种题型。改造后去掉 `CHECK`，
改为外键引用 `subject_question_types(subject_id, type_code)`。

平台预置一组通用题型，学科从中挑选：

| 题型码 | 名称 | 客观 | 判分方式 | 英语 | 生化 |
|---|---|---|---|---|---|
| `single_choice` | 单选 | ✅ | 选项字母精确匹配 | ✅ | ✅ |
| `multi_choice` | 多选 | ✅ | 选项集合比对 | — | 预留 |
| `true_false` | 判断 | ✅ | 精确匹配 | — | 预留 |
| `fill_text` | 文本填空 | ✅ | 归一化后比对 | ✅（原 `fill_blank_transform`） | ✅ **多空** |
| `fill_numeric` | 数值填空 | ✅ | 数值容差比较 | — | ✅ |
| `term_explain` | 名词解释 | ❌ | AI 按**采分点**评分 | — | ✅ |
| `short_answer` | 简答/问答 | ❌ | AI 按**采分点**评分 | — | ✅ |
| `essay` | 写作/论述 | ❌ | AI 按**维度加权**评分 | ✅ | — |

英语迁入时只启用 `single_choice`、`fill_text`、`essay`，行为与现状一致。

**生化的 `in_practice` 配置**：

| 题型 | 进练习 | 理由 |
|---|---|---|
| `fill_text` / `fill_numeric` | ✅ | 客观可判，即时反馈 |
| `single_choice` | ✅ | 同上 |
| `term_explain` | ✅ | 名词解释答案短，AI 评分快且便宜 |
| `short_answer` | ❌ | 问答题答案长，AI 评分慢且贵，只在模考出现 |

这正是蓝本"作文不进练习"那条规则的推广——**不是因为它是主观题，而是因为它慢且贵**。
名词解释同样是主观题但答案只有一两句话，可以进练习。判断依据进配置，不写死。

#### 6.4.5 一题多空（🆕 R2、R4 · 本次最大的模型改动）

**问题**：蓝本 `questions.answer` 是单个 TEXT 字段，`gradeQuestion()` 做单值比较。
生化一道填空题平均 4.2 个空、最多 10 个空，装不进去。

##### 数据模型

新增 `question_blanks` 表，一道题的每个空一行：

| 字段 | 说明 |
|---|---|
| `question_id` + `blank_ord` | 联合主键，`blank_ord` 从 1 开始 |
| `subject_id` | 隔离 |
| `blank_kind` | `EXACT`（单一答案） / `SET_MEMBER`（无序并列组成员） / `ENUM`（受限选择） / `NUMERIC`（数值） |
| `group_key` | 无序并列空的组标识。同组的空共享一个答案集合 |
| `answer` | 标准答案（`ENUM` 时是题干括号里的枚举值之一） |
| `alt_answers` | JSON 数组，可接受的其他写法（归一化器之外的显式别名） |
| `score` | 该空分值 |
| `tolerance` | `NUMERIC` 专用，相对容差 |
| `unit` | `NUMERIC` 专用，单位 |

`questions.answer` 保留：单空题直接用它，多空题置空并以 `question_blanks` 为准。
**这样英语的单空题路径完全不变。**

##### 判分

```
对每个空组（按 group_key 归组，无 group_key 的自成一组）：
   blank_kind = SET_MEMBER → 集合比对：学生答案集合 vs 标准答案集合
                              命中数 / 应答数 × 组总分
   blank_kind = ENUM       → 必须是题干枚举值之一且等于标准答案
   blank_kind = NUMERIC    → 数值容差 + 单位比对
   blank_kind = EXACT      → 归一化后精确比对
题目得分 = Σ 各空得分
```

**部分分开关**：`rubric.objective.partial_credit`。
英语设 `false`（保持"只有满分或零分"），生化设 `true`。

##### 掌握度归属

一道多空题答对 7/10，这个考点算"对"还是"错"？

**规则**：`rubric.mastery.question_correct_threshold`，默认 `1.0`（全对才算对）。
生化建议设 `1.0` —— 掌握度是用来驱动"这个考点要不要再练"的，
**答对 7/10 说明还没掌握，应该继续出**。

这条要写进配置的注释里，避免后人随手调成 0.6 而不知道会导致什么。

##### 错题本粒度

错题本记到**题**，但 `wrong_items` 新增 `wrong_blanks` 字段（JSON 数组，
记哪几个空错了）。学员在错题本里看到的是整题 + 标出自己错的那几个空。

**订正规则不变**：连续答对两次算订正；"答对"用上面的 `question_correct_threshold` 判定。

##### 前端作答控件

`fill_text` 多空题渲染为：题干里的每个空位置一个输入框，按 `blank_ord` 顺序排列。
无序并列组（`SET_MEMBER`）的输入框在视觉上归为一组并注明"顺序不限"。

#### 6.4.6 答案缺失与原题有误（🆕 R7、R8）

##### 缺答案

**附件只有题目，没有答案也没有解析。** 这是生化与英语最大的运营差异。

`questions.status` 从三值扩展为四值：

| 状态 | 含义 | 可被抽题 |
|---|---|---|
| `草稿` | 刚导入，未校对 | ❌ |
| **`缺答案`** 🆕 | 题面已校对，但没有标准答案 | ❌ |
| `已发布` | 完整可用 | ✅ |
| `存疑` | 解析存疑，被扣下 | ❌ |

**答案补全工作流**：

1. 导入后题目进 `缺答案` 状态，后台列表可按此筛选
2. 管理员在校对页逐题录入答案（多空题逐空录入）
3. 可选的 **AI 辅助**：调教学 AI 生成候选答案，**标注为待核**，
   管理员确认后才落为标准答案
4. 全部空都有答案后，状态才能转 `已发布`

**硬约束**：AI 生成的答案**绝不能自动发布**。这是蓝本 `docs/项目全档.md` §9.3 那条教训的直接延伸——
AI 返回结构不符时静默给了 0 分，学生看到的是一个理直气壮的错误。
答案是判分的基准，错一个答案会让所有做对的学生被判错。

**后台看板要显示"缺答案题数"**，它是内容建设进度的核心指标。

##### 原题有误

蓝本的 `exam_parsing_notes` 假设"错误来自解析"。附件第 9 题的选项标号 D 重复，
**错误来自原始资料**。两者处理方式不同：

| 状态 | 含义 | 处理 |
|---|---|---|
| `解析存疑` | 解析可能错了 | 对着原件核对，改解析结果 |
| **`原题有误`** 🆕 | 原始资料本身错了 | 人工订正并**记录订正内容**，或标为废弃 |

`exam_parsing_notes` 新增 `note_kind` 字段区分两者。
`原题有误` 的题目订正后要留痕（订正人、订正时间、原文与改后），
因为"我们改了原题"这件事将来会被质疑。

### 6.5 独立例题解析

#### 6.5.1 题目解析（Explanation）

**现状**：蓝本只有 `questions.answer_explanation` 一个自由文本字段，
外加 AI 事后生成的 `wrong_items.error_analysis` / `memory_point`。
**没有结构，没有来源标记，没有审核状态，没有版本。**

**改造**：新增 `question_explanations` 表，一道题可有多条解析：

| 字段 | 说明 |
|---|---|
| `subject_id` / `question_id` | 归属 |
| `kind` | `OFFICIAL`（原卷官方解析） / `MANUAL`（人工撰写） / `AI`（AI 生成） |
| `content` | JSON，**结构由该学科的 `subject_explanation_schema` 定义** |
| `source_model` | AI 生成时记录模型与时间 |
| `review_status` | `待审` / `已发布` / `已打回` |
| `reviewed_by` / `reviewed_at` | 审核人 |
| `version` | 历史版本保留，展示取最新已发布 |

**解析结构按学科定义**：

| 学科 | 解析字段 |
|---|---|
| 英语 | 定位依据、词义辨析、句子结构、干扰项为什么错 |
| **生化** | **考点出处（章节）、核心概念、推理链条、易混淆点、关联知识点** |

生化的解析结构要点：它的题目考的是**概念记忆与理解**，不是文本定位。
例如"破坏 α-螺旋结构的氨基酸残基之一是（脯氨酸）"，解析要讲的是
**为什么脯氨酸会破坏螺旋**（亚氨基无法提供氢键、侧链环状造成位阻），
而不是"在第几行找到依据"。

**展示优先级**：已发布的 `MANUAL` > `OFFICIAL` > 已发布的 `AI`。
学员侧**必须标明解析来源**："本解析由 AI 生成，仅供参考"。

**AI 生成解析**沿用蓝本的分层原则：主链路不依赖 AI，解析生成是异步补充，
失败不影响做题与判分。

#### 6.5.2 例题（Exemplar）

学科自建的教学用典型题，与题库分开：

- 不来自题库，由学科管理员录入，用于"讲"而不是"考"
- **不进入组卷与练习抽题池**（硬约束，写成测试断言）
- 含：题面、完整解题过程、涉及考点、难度、适用场景说明
- 挂在考点上：学员在错题本或能力评估里看到某个薄弱考点时，可跳去看该考点的例题
- 页面：学员端 `/app/:subjectCode/exemplars`，后台 `/admin/s/:subjectCode/exemplars`

**为什么单列**：题目解析回答"这道题为什么选 C"；例题回答"这类题该怎么想"。
把后者硬塞进题目解析会让解析又长又不聚焦。

生化尤其需要例题：像"蛋白质为什么能稳定溶解于水"这类问答题，
学员需要的是一个**范答 + 答题框架**，这正是例题的形态。

### 6.6 独立评价标准

"评价标准"覆盖六件事，全部按学科配置，存入 `subject_rubrics`（JSON + 版本号）。

#### ① 客观题判分规则

| 参数 | 说明 | 英语 | 生化 |
|---|---|---|---|
| `normalizer` | 归一化器标识 | `english` | `biochem` |
| `case_sensitive` | 区分大小写 | `false` | `false` |
| **`partial_credit`** 🆕 | **按空给部分分** | **`false`** | **`true`** |
| `numeric_tolerance` | 数值相对容差 | — | `0.005` |
| `set_order_matters` | 并列空是否计顺序 | — | `false` |
| `blank_is_zero` | 未作答记 0 分 | `true` | `true` |

**v2 的重要修订**：v1 把"只有满分或零分、不给部分分"写成了跨学科铁律。
实际上它是**英语完形填空的官方评分参考**（蓝本 `docs/prd.md` §4.3 引了原文：
"本部分无 0.5 分和 1 分的计分"），不是通用规则。生化一题 10 个空必须给部分分。

**不变的骨架**（这些才是真铁律）：不做模糊匹配、规则判不对的一律记错、
归一化器只能做等价折叠。

#### ② 主观题评分：两种 rubric 类型

蓝本只有一种形状（作文五维加权）。生化的名词解释与问答题是**采分点命中式**，
形状完全不同。改造为 `rubric.subjective.<question_type>.type` 分派：

**类型 A：维度加权（`DIMENSION_WEIGHTED`）** —— 英语作文

```
{
  type: 'DIMENSION_WEIGHTED',
  scale: 6,                    每个维度的打分上限
  total_score: 30,
  dimensions: [
    { key: 'content',    name: '内容要点覆盖', weight: 0.30 },
    { key: 'language',   name: '语言准确性',   weight: 0.25 },
    { key: 'vocabulary', name: '词汇丰富度',   weight: 0.15 },
    { key: 'coherence',  name: '篇章连贯性',   weight: 0.20 },
    { key: 'length',     name: '字数达标',     weight: 0.10 }
  ]
}
```

迁入时填现有值，**由测试断言新旧算法在同一组输入下得分完全一致**。

**类型 B：采分点命中（`SCORE_POINTS`）** 🆕 —— 生化名词解释与问答题

```
{
  type: 'SCORE_POINTS',
  total_score: 5,
  points: [
    { key: 'p1', desc: '氨基酸的羧基与另一氨基酸的氨基脱水缩合', score: 2 },
    { key: 'p2', desc: '形成的酰胺键即肽键',                   score: 2 },
    { key: 'p3', desc: '具有部分双键性质，不能自由旋转',         score: 1 }
  ],
  hit_policy: 'AI_JUDGE',      AI 逐点判定是否命中
  allow_partial_point: false   单个采分点不拆分，命中即全给
}
```

**采分点存在题目上**（`question_blanks` 之外新增 `question_score_points` 表），
因为每道题的采分点都不同；`subject_rubrics` 只定义**这个学科用哪种类型、总分怎么算、
AI 怎么判**。

**AI 调用形状**：给 AI 题目、采分点清单、学生答案，要求返回每个点是否命中 + 理由。
得分 = Σ 命中点的分。**这比让 AI 直接打总分可靠得多**——它把主观判断拆成了一组
可核对的二元判断，管理员事后能看出 AI 判错了哪个点。

**保留蓝本的关键约束**：AI 返回里一个采分点都读不到时必须抛 `ai_bad_shape`，
**绝不静默回落 0 分**。真的 0 分和读不到 0 分必须分得开。

#### ③ 掌握度分档阈值

现状写死在 `mastery.js`。改造为配置：

```
rubric.mastery = {
  min_questions: 3,                  已掌握所需最少做题数
  min_streak: 3,                     已掌握所需连对次数
  weak_accuracy: 0.5,                低于此正确率判为薄弱
  question_correct_threshold: 1.0    🆕 多空题得分率达到多少才算"答对"
}
```

#### ④ 自适应抽题权重

现状 `tagWeight()` 写死 2.0 / 5.0 / 2.0 / 1.0 / 0.3。改为配置表。

**"连对三次也不归零（保底 0.3）"的设计意图必须在配置里写明注释**——
它是为了复验"蒙对"的考点，学科改这个值时要知道自己在改什么。

#### ⑤ 能力评估参数

| 参数 | 现状 | 改造 |
|---|---|---|
| 时间衰减权重 | `[0.35, 0.25, 0.20, 0.12, 0.08]` 写死 | 按学科配置 |
| 最少样本数 | 2 次模考 | 按学科配置 |
| 预测区间宽度 | `max(3, 历史标准差)` | 按学科配置下限 |
| 满分 | 100 写死在裁剪逻辑里 | 取课程满分 |
| 及格线 | 无 | 🆕 按学科配置，报告显示"距及格还差 X 分" |

**双层结构不变**：统计层与 AI 层并列呈现、互不覆盖。

**生化的特殊性**：它的主路径是章节练习而非模考，所以能力评估的样本来源要放宽为
"模考 + 练习"，并按学科配置权重。否则一个只做章节练习的生化学员永远拿不到评估。
这是 `rubric.assessment.sample_sources` 参数。

#### ⑥ 错题订正阈值

现状 `CORRECT_STREAK_TO_CLEAR = 2`。改为按学科配置，默认 2。

### 6.9 跨学科视图

**后台** `/admin/overview`：

**权限实现要求**：

1. JWT 只携带 `user_id` 与全局角色，**学科授权不进 JWT**（理由见 §6.2.2）
2. 所有 `/api/admin/*` 强制校验全局角色

   只校验"他是学科管理员"不够，必须校验"这条资源是不是他那个学科的"

### 11.4 部署流水线

沿用蓝本 `deploy-worker.yml` 的步骤结构与**步骤顺序**——顺序本身是踩坑改出来的：
部署必须排在数据装载之前，否则导入一失败后面的部署整步跳过，修复代码永远上不了线。

（该工作流实测有 20 个命名步骤，蓝本 `docs/项目全档.md` §8.2 记作"22 步"，
以工作流文件为准；改造时顺手把蓝本文档这处数字改对。）

新增步骤：

```
… → 执行迁移 → 部署 Worker → 写入密钥
  → 🆕 创建学科（english、biochem）
  → 🆕 按学科逐个导入题库（指纹跳过 + 每学科单独一步，便于定位失败）
  → 放行题库 → 等待响应 → 初始化平台管理员
  → 🆕 初始化学科授权
  → 取管理员令牌 → 配置 AI → 线上验证 → 输出汇总
```

**线上验证必须保留蓝本的"写入哨兵"断言**（`写入已恢复（AI 配置 N 秒前刚落库）`）：
D1 写配额耗尽时所有读接口都正常、只有写会失败，十几条读类断言全绿说明不了站点能用。

**新增三条验证断言**：

- 跨学科越权：用只授权英语的探针账号访问 `biochem`，必须 403
- 学科隔离：英语组卷结果里不得出现任何生化题目，反之亦然
- **多空判分**：生化一道 10 空题答对 7 空，得分必须是 7 空的分值之和，不是 0 也不是满分

| AI 类接口 | < 30s，且有加载态 |
| 学科切换 | < 500ms（只换上下文，不重载整个应用） |
| **多空题判分** 🆕 | 一题 10 空的判分 < 50ms（纯本地计算，不调 AI） |

### 12.2 安全

| 项 | 要求 |
|---|---|
| 密码 | bcrypt 加盐哈希 |
| JWT | 8 小时过期，只带 `user_id` 与全局角色 |
| 登录限流 | 连续 5 次失败锁 10 分钟 |
| API Key | 服务端 AES-GCM 加密存储，读出脱敏（`sk-****3456`），明文绝不下发前端 |
| 用户数据隔离 | 强制按 `userId` 过滤，不接受前端传入 |
| **学科数据隔离** | 🆕 强制按中间件解析的 `subject_id` 过滤，不接受请求体传入 |
| **权限撤销时效** | 🆕 ≤ 60 秒全网生效 |
| **越权审计** | 🆕 所有 `subject_forbidden` 响应记日志，便于发现探测行为 |
| **标准答案不下发未作答的题** | 🆕 多空题的 `question_blanks.answer` 只在交卷/判分后返回 |
| 仓库公开时 | 凭据只进 GitHub Secrets 与 Worker Secrets |

**倒数第二条是新增的实际风险**：多空题的作答接口要返回空的数量与位置，
很容易顺手把 `question_blanks` 整行返回，**标准答案就随着题目一起发到前端了**。
英语单空题因为答案在 `questions.answer` 且取卷时被显式排除，没暴露这个面。

### 12.3 容量与配额

D1 免费档每天 10 万行写入，世界时零点（北京时间早八点）重置。
蓝本实测：**英语 20 套真题、1020 道题的完整重导约 5700 行写入。**

生化估算（按附件规模外推）：

| 项 | 估算 | 依据 |
|---|---|---|
| 章节数 | 20～25 章 | 生化与分子生物学教材通用结构 |
| 每章题量 | 35 道 | **附件实测**（填空 12 + 选择 14 + 名词解释 7 + 问答 2） |
| 总题量 | 700～875 道 | 章节数 × 每章题量 |
| **额外的空** | **约 1000～1250 行** | 每章 50 个空 × 20～25 章 |
| 采分点 | 约 400～500 行 | 名词解释与问答题每题 3～5 个采分点 |
| 完整导入写入量 | **约 4000～5000 行** | 无 `passage_text` 大文本，比英语略少 |

| 学科数 | 首次全量导入 | 是否撞上限 |
|---|---|---|
| 2（英语 + 生化） | ~10,000 | 否，余量充足 |
| 10 | ~50,000 | 否 |
| 17 | ~96,000 | **逼近上限** |

**要求**：

1. **种子指纹机制（`seed_state`）原样保留并按学科分文件**，稳态部署写入量为 0
2. 导入按学科**分步执行**，一个学科失败不拖垮其他学科，日志里直接看出是哪个学科
3. 导入前**预估并打印行数**，接近额度时主动中止并提示"明日继续"，
   而不是撞上去半途失败留下脏数据
4. **内容指纹必须与数据同批入库**（蓝本踩过的坑：分两步写，数据进去了指纹没记上，
   下次重导再死在同一处，每跑一次白烧几百行，永远走不出来）
5. 配额耗尽时降级方向是"写不进"而不是"打不开"

**两个学科的规模完全在免费额度内**，学科数超过 10 个时需要重新评估（§16）。

### 12.4 可扩展性

| 项 | 要求 |
|---|---|
| 新增结构相似的学科 | 纯配置 + 数据，零代码 |
| 新增需要新判分语义的学科 | 新增 1 个归一化器 + 其单元测试，不改既有学科代码 |
| 新增资料格式 | 新增 1 个导入器，注册进管线表 |
| 新增题型 | `subject_question_types` 声明 + 前端注册一个控件，不改判分骨架 |
| 修改评价标准 | 纯配置，不改代码，且不影响历史报告 |

### 12.5 测试

沿用蓝本的四层测试策略（240 条断言）并扩充：

| 层 | 新增内容 |
|---|---|
| 单元测试 | 归一化器的等价与**非等价**用例；**多空判分的各种组合**（全对/全错/部分对/无序并列/数值容差） |
| 单元测试 🆕 | 采分点式评分的取分宽容度与 `ai_bad_shape` 抛出 |
| 单元测试 🆕 | **docx 导入器**：跑附件这一章必须产出 35 道题、50 个空 |
| 冒烟测试 | 每层都要有"两个学科并存"的场景，不能只测单学科 |
| **越权测试** | 🆕 无授权、授权过期、授权停用、学科停用、跨学科读写、`SUBJECT_ADMIN` 越学科 |
| **隔离测试** | 🆕 组卷/练习/错题本/报告的结果集里不得出现他学科数据 |
| 浏览器实测 | 学科选择、学科切换、无权限空状态、**多空作答控件在手机上的可用性**，三种宽度 |
| 线上端到端 | 新增 §11.4 的三条断言 |

**沿用蓝本的测试纪律**（来自返工六次的教训，已沉淀为 `dev-standards`）：

- 每条断言写完，把被测逻辑临时改成返回常量跑一次，确认变红
- 期望值和被测值不能同源
- 挑样本前先确认它在被测流程里真的可达，并把决定可达性的属性打印出来
- 每套测试占独立端口，加新测试前先查端口表
- 跑测试时 `|| echo "!! 没有小结"` 不能省，否则会把"脚本提前退出"误读成"通过"
- AI 替身只测协议约束与降级路径，**不用来证明功能可用** ——
  它对时延和返回结构结构性失明

**生化的 AI 替身要新增采分点式返回形状**，并且要有一条"返回的采分点 key 与题目
对不上"的用例——这正是蓝本 `docs/项目全档.md` §9.3 那个"静默 0 分"事故在新场景下的复现形态。

### 13.2 生化：内容建设是独立工作流

**这是与英语最大的运营差异，必须单独排期。** 英语题库"拿来就能用"，
生化题库要经过三道人工关口才能上线。

| 阶段 | 工作 | 产出 | 谁做 |
|---|---|---|---|
| ① 资料收集 | 收齐各章习题 docx | 20～25 个 docx | 内容方 |
| ② 机器导入 | 跑 docx 导入器 | 题库 JSON（题面齐全、**答案为空**） | 系统 |
| ③ 题面校对 | 核对题号、选项字母、跨段题干；处理**原题有误** | 题面可信 | 学科管理员 |
| ④ **答案录入** | 逐题逐空录入标准答案 | 状态从 `缺答案` 转 `已发布` | 学科管理员 |
| ⑤ 考点标注 | 给每题挂考点（两级：章 → 知识点） | 自适应练习可用 | 学科管理员 |
| ⑥ 采分点拆分 | 名词解释与问答题拆采分点 | 主观题可 AI 评分 | 学科管理员 |
| ⑦ 解析补全 | AI 生成 + 人工审核 | 解析可用 | AI + 学科管理员 |

**工作量提示**：按附件规模，每章 35 道题、50 个空。
④⑤⑥ 三步是**逐题人工**，一章按 1～2 小时估，20 章就是 20～40 小时。
**这是生化上线的关键路径，不是系统开发工作量，但会决定上线时间。**

**可以做的加速**：

- ④ 答案录入提供 AI 辅助生成候选，人工只做确认与修正（**绝不自动发布**，§6.4.6）
- ⑤ 考点标注可以先按章粗标（一级考点 = 章），细化留到后面
- ⑥⑦ 可以只先做高频题，其余随用随补

**分批上线是允许的**：`已发布` 的章节就能练，`缺答案` 的章节不参与抽题。
不必等全部 25 章都完工才上线。

| **N5 多空与采分点** 🆕 | `question_blanks`、`question_score_points`、判分骨架改造、多空作答控件、采分点式 AI 评分 | B5～B13 通过（用构造数据，不依赖真实题库） |
| **N6 生化导入管线** 🆕 | docx 导入器、生化归一化器、内容组织维度放宽、缺答案与原题有误状态 | B1～B4、B14 通过 |
| **N7 报告分层** | 所有报告加学科维度；修后台看板无过滤缺陷；跨学科汇总视图 | F5/F6/F7 通过 |
| **N8 解析与例题** | `question_explanations`、`exemplars`、审核流、动态解析渲染器 | F8 通过 |
| **N9 生化上线** | 内容建设（§13.2 七步）+ 全链路跑通 | B15、A1、A2 通过 |
| **N10 验收** | 全套回归、越权测试、隔离测试、浏览器实测、线上端到端 | §14 全部通过 |

**关键路径有两条，可以并行**：

- **系统路径**：N0 → N1 → N2 → N3 → N4 → N5 → N6 → N7 → N8
- **内容路径**：资料收集 → 题面校对 → 答案录入 → 考点标注 → 采分点拆分（§13.2）

**内容路径不依赖系统路径的后半段**：N6 一做完就能开始批量导入与人工录入。
按 §13.2 的估算，内容建设 20～40 小时是**生化上线的真实瓶颈**，
越早开始越好，不要等系统全做完。

**N5 要在 N6 之前**：先用构造数据把多空判分做对做稳，再接真实导入。
反过来做的话，判分 bug 和导入 bug 会缠在一起，很难分清是哪一层的问题——
这正是蓝本"测试测的不是它以为的东西"那类返工的温床。

## 附录 A：蓝本关键设计的保留清单

改造过程中**不允许被改掉**的蓝本设计决策，每一条背后都有踩过的坑：

| # | 设计 | 出处 |
|---|---|---|
| 1 | 鉴权中间件按前缀挂，绝不挂 `/api/*` | 挂了会挡住健康检查与登录 |
| 2 | `run_worker_first = ["/api/*"]` | 少了这行未知接口返回 HTML，前端拿去 `JSON.parse` |
| 3 | AI 调用强制 `enable_thinking: false` | 推理模型不关思考会把 token 花光返回空对象，延迟从 3s 涨到 15s+ |
| 4 | AI 只增强体验，主链路不依赖 AI | 交卷先出客观题成绩，AI 事后补 |
| 5 | **AI 返回读不到关键字段必须报错，不静默回落 0** | 线上出过"理直气壮的零分"。**采分点式评分要继承这条** |
| 6 | AI 错题分析并发上限 5 | 串行会让请求 80 秒以上超时；替身测不出来 |
| 7 | 错题在判分时落库，不等 AI | AI 不可用时错题本照常能用 |
| 8 | 配额耗尽的降级方向是"写不进"不是"打不开" | 记账写入失败不该把人挡在登录外 |
| 9 | 内容指纹与数据同批入库 | 分两步写会导致永远走不出重导循环 |
| 10 | 部署步骤排在数据装载之前 | 导入失败会让修复代码永远上不了线 |
| 11 | **判分不做模糊匹配，宁可判错记错** | "双写 l 简化"会把 `filled` 判成 `filed`。**生化归一化器要继承这条** |
| 12 | 抽题权重连对三次也不归零 | 要复验"蒙对"的考点 |
| 13 | 组卷凑不满返回 422，不出残缺卷子 | |
| 14 | 每套测试占独立端口 | 撞过一次，症状是随机的、与改动无关的失败 |
| 15 | 跑测试必须检查"小结"是否存在 | 脚本可能提前退出，"没有 FAIL"不等于通过 |
| 16 | AI 替身不用来证明功能可用 | 它对时延和返回结构结构性失明 |
| 17 | 线上验证必须有写入哨兵 | 读接口全绿说明不了站点能用 |
| 18 | 条形图用 HTML 不用 SVG | SVG 字号随 viewBox 缩放，手机上 12px 只剩 7.7px |
| 19 | 练习已答计数从服务端取 | 只存前端状态时刷新会归零 |
| 20 | 单一选项时不显示选择器，但判断写"数量 > 1" | 将来加第二个不用回头改页面 |
| 21 | 解析不确定处必须写进 `parsingNotes` 并**写明题号** | 蓝本靠这个机制扣下了 125 道存疑题 |

**第 5、11、21 条在生化场景下尤其重要**：

- 第 5 条 → 采分点式评分是新的 AI 返回形状，最容易重演"静默 0 分"
- 第 11 条 → 氨基酸等价表很容易写过头，把 `谷氨酸`/`谷胺酸` 折到一起
- 第 21 条 → docx 导入器面对三种编号约定并存，拿不准的必须记下来而不是猜

**第 20 条值得单独说**：蓝本处理"只有一门课程"时就是这么写的，
本次学科选择页沿用同样的思路（§6.3.1）。蓝本作者已经预见到了扩展的可能——
本次改造是把这个预留真正用起来。
