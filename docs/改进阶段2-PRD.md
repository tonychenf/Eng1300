## 4. 全局规则（每个新页面、新接口都要遵守）

### 4.1 手机优先
- 三种宽度都能走完：手机 390、平板 768、PC 1280（浏览器测试就测这三种）；手机上不出现横向滚动。
- 触控目标 ≥ 44px；输入框字号 ≥ 16px。
- 表格在手机上变成卡片（每行一张卡），不横向滚动。
- 长任务（识别、批量发布）关掉页面不影响结果；回来能看到进度。

### 4.2 管理员不碰 JSON、不起英文编号
- 学科码给一个默认值（`s` + 两位序号，如 `s04`），页面提示"建议改成好记的英文，如 pubeng"，可改，建好后不能改；内容组编号、课程码自动生成。
  不做中文转拼音：那要引一个前端库，而 KaTeX 是项目里唯一引入的前端库（CLAUDE.md）。
- 评价标准不再有 JSON 文本框给普通操作用（能力包页的 JSON 编辑保留为"高级"折叠项）；本期暴露的开关见 P1-A3。

### 4.3 AI 生成的东西一律标出来
题面、答案、采分点、考点凡是 AI 出的都带「AI」小标记（现有 `answer_source = 'AI'`、考点 `kp-ai-` 前缀已能判断）；人确认后去掉。

### 4.4 花钱、耗时的操作先预估、再确认
弹窗格式统一：「共 41 页，预计 6 分钟，预计花费约 0.8 元。本月已花 3.2 元 / 上限 20 元。」→「开始」「取消」。
做完显示实际花费。预估 = 页数（或题数）× 第二期实测的单价；没有实测单价时显示「花费未知」并仍要确认。

### 4.5 审计
新增表 `admin_audit`（第 8 节），以下动作各写一行：建学科、改课程满分 / 时长、改组卷模板、整组确认答案、一键发布、一键开通、
改每月花费上限、继续超额、合并 / 改名考点、导入任务入库 / 放弃。写审计失败**不拦主操作**（记账类，吞掉并 `console.warn`）。

### 4.6 错误
接口错误统一 `{ error: <码>, message: <给人看的中文> }`；页面直接显示 message。读不到配置就报错，不回落默认值。

### 5.2 A 新建学科开箱可用

#### P1-A1 「开一门新课」表单
入口：后台「学科管理」页顶部按钮「开一门新课」，进入开新课引导第 ① 步（5.4）。

| 字段 | 必填 | 默认 | 校验 |
|---|---|---|---|
| 学科名 | 是 | — | 1–20 字，和已有学科不重名 |
| 学科码 | 是 | `s` + 两位序号（见 4.2），可改 | 沿用现有 `SUBJECT_CODE_RE`（`lib/subject.js:49`，2–20 位、小写字母开头、可含数字和连字符），不另写一条；不重复；提示"建好后不能改，会出现在网址里" |
| 参照哪门课 | 否 | 「不参照」 | 下拉：已有的每个启用学科 + 「不参照（用通用题型）」 |
| 满分 | 是 | 100 | 1–1000 的整数 |
| 考试时长（分钟） | 是 | 120 | 10–600 的整数 |

其余两个学科属性不让选，按规则定：`content_group_kind = 'TEXTBOOK_CHAPTER'`；`ingest_pipeline` 第一期是 `json-direct`（P1-I1 的题库文件导入），
第三期上线后新学科改为 AI 拆题。**参照生化也不复制 `docx-structured`**：那条 Word 管线只认生化版式，拍板 12 定了留给生化专用。

提交 → **先在内存里验，再写库**：把要写的能力包各行在内存里拼成能力包对象，用读能力包时的同一套校验
（题型的判分策略 `resolveGrader`、评价标准的校验）先过一遍，过不了就 422 `subject_pack_broken` 并说清哪一项，一行都不写。
过了才发一个 `db.batch`：`subjects`、`courses`（课程码 `<学科码>-main`，课程名 = 学科名）、能力包各表、审计。batch 里任一句失败整批不落库，不会出现"有学科没课程"。

#### P1-A2 复制能力包的规则
| 表 | 参照某学科时 | 不参照时 |
|---|---|---|
| `subject_question_types` | 逐行复制（类型码、名称、判分策略、形态、控件、归一化器、排序都照抄） | 三行通用题型，**都照抄生化**的同码行（英语和生化的 `fill_text` 归一化器不同，统一抄生化那份）：`single_choice` 单项选择、`fill_text` 填空、`short_answer` 简答（按采分点 AI 批）。填空题在前端走"一空一框"（`question_items` 的输入单元）；没有得分单元、只有单个 `answer` 的填空题会被显示成"给定词："那种样式（`questions.jsx:108`），所以导入时填空题一律落成得分单元 |
| `subject_rubrics` | 复制 `is_current = 1` 那一版，新学科记为第 1 版 | 一份通用评价标准：`partialCredit: true`、`essay.type: POINT_HIT`、`mastery` 照公共英语那份（"算答对"的门槛见待确认 6） |
| `subject_explanation_schema` | 复制 | 通用：`{解析, 考点}` 两个字段 |
| `subject_ai_prompts` | 复制该学科自己的行；把正文里的原学科名替换成新学科名；替换后仍含原学科名以外的学科专有词无法判断，所以**只做学科名替换**，并把"复制来的提示词"列在建好后的提示里：「这 4 条提示词是从公共英语复制的，学科名已替换，建议看一眼」 | 主观题批改（`essay_grade`）**抄生化那份按采分点批的**（全局默认那份写的是"学生作文 / 写作要求"，`0009:224-234`，给简答用会让模型按作文打分）；其余三条用全局默认（`subject_id = 0` 的行） |
| `subject_settings` | 复制 | 不写：没配的参数回落到全局 `system_settings`（`subject-pack.js:172-186`） |
| 题目、考点、组卷模板、学员授权 | **不复制** | — |

batch 提交之后就生效了，没有事务可以撤回。所以写完再真读一次 `loadPack(新学科)` 当兜底：万一读不出来（内存校验和真读不一致），
发一个补偿 batch 把刚建的学科、课程、能力包删掉，再报 500 并带上读包的报错（这说明两套校验对不上，是要修的 bug）。
以前"建出来能力包读不出来"是 BRD 第 1 节第一行的问题，这一条就是它的验收。

**验收**：手机宽度建一门参照公共英语的新课 → 直接进 ② 传资料、导入页不报"名下还没有课程"；建一门不参照的 → `GET /admin/subjects/:id/pack` 200，题型 3 个；两门课的 `loadPack` 都不抛错；
故意让内存校验过不了（如参照的学科某题型判分策略是空的）→ 422、库里没有新学科的任何一行。

#### P1-A3 评价标准的说人话开关
能力包页「评价标准」区块顶部加三个开关（写回 `subject_rubrics` 新一版，JSON 框折叠为「高级」）：
- 「多空题、按采分点的题给部分分」→ `grading.partialCredit`
- 「英文答案不区分大小写」→ `grading.caseSensitive` 取反

（第 1 版还有一个「及格线」开关，删了：`passLine` 现在没有任何代码在用，只在 `subject-pack.js:15` 的注释里出现，开关拨了也不起作用。）

#### P1-A4 改课程的满分、时长
学科管理页每门课一行「满分 100 · 120 分钟 · 改」。保存 → `PATCH /admin/courses/:code`。只影响以后组的卷（已有作答的 `attempts` 存了当时的时长和分）。
保存后若组卷模板总分 ≠ 新满分，页面黄条：「组卷模板加起来是 95 分，和满分 100 对不上，学员暂时组不了卷 → 去改模板」。
（模板总分对不上时组卷接口回 422 `template_total_mismatch`，不组出一张总分错的卷。**上线顺序**：先在线上验证里加一条"每门课模板合计 = 满分"，
部署一次、看它绿了，再打开这个拦截——否则线上某门课的数据要是本来就对不上，一上线那门课的模考就当场不可用。）

#### P1-A5 上传页不再手填编号
适用于新的导入（P1-I1 题库文件导入、第三期 AI 拆题）：内容组编号 = `<学科码>-<北京日期 yyyymmdd>-<当天序号>`（如 `pubeng-20261107-1`），
不从文件名转写——中文文件名转写出来是空的；显示名 = 文件名去扩展名；排序键 = 本学科现有最大值 + 10。三项都在"高级"里可改。
**生化的 Word 上传不动**：它把排序键当章号用（`admin-import.js:125、180`，传进管线做 `chapterNo`），改成"最大值 + 10"会改掉生化的语义，和拍板 12 冲突。

### 5.3 B 组卷模板

#### P1-B1 页面
路由 `/admin/subjects/:id/template`。入口：学科管理页每门课「组卷模板」、上线清单、开新课引导第 ④ 步。
- 顶部：满分、当前合计（合计 ≠ 满分时红字"还差 5 分"或"多了 5 分"）。
- 表格（手机上每行一张卡），每行一个部分：

| 列 | 控件 | 说明 |
|---|---|---|
| 名称 | 文本 | 学员在作答页、报告里看到的部分名（P1-X5 用的就是它） |
| 从哪类题里抽 | 下拉 | 选项 = 本学科的题型 + 本学科已有的大题类别（`sections.type` 去重），显示中文名；存成 `filter.questionTypes` 或 `filter.sectionTypes` |
| 怎么抽 | 两个按钮「一道一道抽」「整篇抽」 | 对应 `pick_unit` QUESTION / SECTION；下面一行灰字："阅读、完形、段落填空这类带文章的选整篇抽"。选「整篇抽」时"从哪类题里抽"只能选大题类别 |
| 抽几题 | 数字 | 1–200 |
| 每题几分 | 数字 | 0.5 的倍数，> 0 |
| 小计 | 只读 | 抽几题 × 每题几分 |
| 体检 | 只读 | "可选 3 篇 / 需要 1 篇 ✓" 或红字"可选 4 题 / 需要 5 题，差 1 题" |

- 行可拖动排序、删除、加一行。底部「保存」。

#### P1-B2 按样卷生成草稿
「配组卷」页没有模板时，顶部卡片「按一份样卷生成草稿」→ 选本学科一个内容组 → 生成：
- 该内容组每个大题（`sections` 按 `ord`）生成一行：名称 = 大题类别名（同类别第二个起加"（二）"）；
  筛选：这个大题里的题只有一种题型、且这个题型在本学科只出现在这一类大题里 → 按题型筛（如拼写单词、三种翻译）；
  否则按大题类别筛（如选择填空、段落填空、阅读理解，它们都是单项选择题，只能靠大题类别分开）；
  抽法：有原文（`passage_text` 非空）的整篇抽、抽几题 = 这篇下的题数，没有原文的一道一道抽、抽几题 = 题数；
- 每题几分：留空（红框），你照试卷说明填；填完合计 = 满分才能保存。
- 生成的是草稿，不落库，直到你点保存。

验收：对公共英语样卷 2 生成的草稿，和 `data/subjects/pubeng/exam-template.json` 逐行比：名称、筛选、抽法、题数都一致（分值你填）；测试里从这个文件现算期望，不写死。
（已核对样卷 2 的 8 个大题：拼写、词组、句子、段落翻译各是单一题型，选择填空、段落填空、两篇阅读都是单项选择，按上面的规则正好生成文件里的写法。）
界面上「整篇抽」时"抽几题"的意思是"一篇有几题、只抽一篇"，表头随抽法变成"每篇几题"。

#### P1-B3 保存校验（全部通过才写库）
1. 合计 = 课程满分（拍板 3，差额精确到 0.01，浮点比较用分为单位的整数）；
2. 每行的题型 / 大题类别是本学科有的；
3. 整篇抽只能按大题类别筛；

5. 防两人同时改：`courses` 加一列 `template_version`（整数，默认 0）。页面加载时拿到当前版本号，保存时带上。

保存 = 一个 batch，按写入守卫的规矩（`lib/write-guard.js`，CLAUDE.md 四之二）写：守卫条件 = `courses.template_version = 带来的版本号`，
删旧行、插新行、审计每一句都带这个条件；让守卫失效的那句——`UPDATE courses SET template_version = template_version + 1 … AND template_version = ?`——排在最后；

### 5.6 G 学员侧

#### P1-G1 翻译练习每道都 AI 批（拍板 9）
**适用范围**：练习里交上来的题，题型判分策略为 `AI_SCORE_POINTS` 的，且所属学科开着 `subjects.practice_ai_grading`（新列，0/1；见第 12 节待确认 3）。
公共英语三种翻译是这一类；生化名词解释、问答也是同一套逻辑。开关关着的学科照旧"练习不判分"。

**流程**（改 `POST /practice/:id/answer`）：
1. 现有校验照旧（练习进行中、题属于本次练习、作答合法、没答过）；
2. 作答为空 → 不调 AI，直接 0 分（同模考）；
3. 查缓存 `practice_ai_cache`：键 = 用户、题、`sha256(作答)`、`sha256(这道题的采分点 + 批改提示词的正文)`。命中 → 直接用缓存结果，不计次数、不花钱。
   键里带采分点和提示词的指纹：后台改了采分点或提示词，旧缓存自然不再命中，不会返回按旧采分点批的结果；
4. 没命中 → 查今日次数 ≥ `limit.practice_ai_per_day`（默认 100）→ 不调 AI，回自评模式（见下"降级"），
   提示「今天的 AI 批改用完了，明天再来；这次先对照采分点自己看看」。
   **今日次数按 `ai_usage_logs` 数**（`user_id` = 本人、`feature = 'practice_point_grade'`、本北京日），**失败的调用也算**——
   第 1 版按缓存行数算，失败和降级不写缓存，"再批一次"就能无限调 AI；
5. 查本月花费 ≥ 每月上限 → 同样降级，提示「本月的 AI 批改额度用完了，先对照采分点自己看看」；
6. 调 `gradeScorePoints`（模考批改的同一个函数、同一份提示词，学员作答照样包分隔符），但**记账的功能名换成 `practice_point_grade`**
   （模考批改现在记的是 `essay_grade`，`tutor.js:294`；不换的话花费页分不出练习和模考）→ `grade.js` 判分循环得 `scoreRate`、`itemResults`；
   `isCorrect = scoreRate ≥ 评价标准 correctThreshold`（公共英语现在是 1.0，即采分点全答到才算对）；
7. 一个 batch（带现有 `practiceAnswerGuard`，作答记录排最后）：写缓存、掌握度、错题本、作答记录（`ai_judged = 1`、`ai_comment`）、AI 用量；
8. 返回（在现有字段上加）：`aiGraded: true`、`scoreRate`、`itemResults`（每个采分点 `hit`、`reason`）、`items`（采分点原文）、`referenceAnswer`。

**时限**：`chat()` 现在没有超时（`ai.js:96` 的 fetch 不带中止），`chatJSON` 读不懂会再试一次。这里新加：单次调用 20 秒中止，
连重试在内整个批改最多 45 秒；页面转圈超过 10 秒时提示"AI 有点慢，再等等"。（给 `chat()` 加可选的超时参数，不改其他调用的行为。）

**降级（AI 没批出来）**：超时、`ai_bad_shape`、服务商报错、额度用完 →
作答照存（`is_correct = NULL`），返回 `selfCheck: true` + `aiError: { code, message }`；**不显示 0 分**。
页面显示采分点清单让学员自评，并给「再让 AI 批一次」按钮（额度用完时不显示按钮）。重试 = 带同一作答再调这个接口：
因为 `is_correct` 还是 NULL，"答过没有"的检查放行；批成功后按第 7 步写入。

**页面**（练习页反馈区）：
- 交卷按钮按下后显示「AI 正在批改…」（转圈，不可重复点），一般 3–10 秒；
- 批完：顶部「得分 2/3 · 采分点答到 2 个，共 3 个」；采分点逐条 ✓ / ✗ + 一句理由；下面「参考译文」；
- 不再出现"练习不判分"。
- 练习小结页：AI 批过的题计入正确率（按 isCorrect），自评的题照旧不计。

**练习的分**只进本次练习记录、掌握度、错题本；不进成绩报告、历史成绩（练习本来就不计分）。

**验收**（替身）：
- 写对全部采分点 → 得分满、"答对了"；写对部分 → 显示部分得分、进错题本；
- 同一作答再交一次（新练习里同一道题）→ 不调 AI（替身记录的调用次数不变），结果相同；
- 把上限设成 2：第 3 道新作答降级为自评，提示今天用完；
- 替身返回照抄示例 / 超时 → 自评 + 重试按钮，页面无 0 分；重试成功后正常显示；
- 并发：同一题两个请求同时到，作答记录一条（`submit-race` 那套 node 内 D1 替身里断）。两次 AI 调用挡不住（守卫只挡写入），两次都记账、都算今日次数——这是上限兜着的已知代价，不另加锁；
- 采分点改了之后同一作答再交 → 重新调 AI（缓存键变了）；
- 花费：按替身自己记下的 tokens × 单价现算期望，对 `ai_usage_logs.cost_yuan`。

|---|---|---|
| 分辨率 | 短边 < 1000 像素 | 红：「太小，请靠近一点重拍」 |
| 模糊 | 灰度拉普拉斯方差 < 100 | 红：「拍糊了」 |
| 亮度 | 平均灰度 < 60 或 > 230，或过曝像素 > 5% | 红：「太暗 / 反光」 |
| 歪斜 | 文字行倾角 > 5°（水平投影法） | 黄：自动纠正后显示，看不清再重拍 |
| 没拍全 | 四边 3% 宽的条带里有文字像素 | 黄：「边上可能被裁掉了」 |

- 红的必须重拍或删掉才能点「开始识别」；黄的提示后可以继续。可拖动调页序、删页、单张重拍。
- 压缩到实测定的尺寸（JPEG），逐张上传进任务。一次最多 60 页。
- 点「开始识别」→ 4.4 的预估确认弹窗 → 任务进「待识别」。

#### P3-C2 后台排队（拍板 4）
- `wrangler.toml` 加 `[triggers] crons = ["* * * * *"]`（免费计划可用）；`scheduled` 处理器每分钟取一批「待识别 / 识别中」的页（每批页数实测后定，起始 4 页、并发 2），
  每页一次读图调用（同时让模型读出书上印的页码），写回文字。
- 单页失败重试 2 次；仍失败的页标「失败」，其余照常；任务整体在所有页有结果后进入拆题。
- 拆题：整份文字（按页序拼接，保留"第 X 页"分隔）一次文本调用（太长按大题边界分段），输出结构见下；然后对每道题跑一次现有"出答案、采分点、考点"（AI），做题反查一起出。
- 进度页（任务详情）显示：已识别 N / 共 M 页、预计还要几分钟、已花多少；完成后后台首页提示「公共英语导入：识别完了，有 6 处要你看」。

**拆题输出结构**（AI 只能填这些字段；校验不过整段重试一次，再不过记"拆题失败"并保留文字）：
```json
{ "sections": [ { "type": "<本学科大题类别或题型名>", "title": "...", "passage": "...|null",
    "printedCount": 25, "pages": [121],
    "questions": [ { "no": 1, "questionType": "<本学科题型码>", "stem": "...",
                     "options": ["A. ...", "B. ...", "C. ...", "D. ..."] | null,
                     "handwrittenAnswer": "C" | null, "page": 121, "doubt": "..." | null } ] } ] }
```

#### P3-C3 第二道关：自动体检（规则逐条）
| 规则 | 判定 | 可疑处挂在 |
|---|---|---|
| 页码连续 | 识别出的印刷页码按上传顺序应 +1；缺、重、逆序 | 任务顶部，提示补拍第几页 |
| 题号连续 | 每个大题内 `no` 从 1（或接上一页）连续，不跳不重 | 跳号处 |
| 选项齐全 | 选择题选项数 = 本学科该题型的选项数（默认 4），字母 A–D 不缺不重 | 那道题 |
| 题量对得上 | `printedCount`（如"(1×25)"）≠ 实际题数 | 那个大题 |
| 段落填空 | 原文里的空号集合 = 题号集合；词库词数 = 声明数（如 15） | 那篇 |
| 阅读 | 篇章下的题数 = 声明数 | 那篇 |
| 乱码 | 非常用字符（替换符、控制字符、孤立的组合符）出现 | 那行 |
| 不成词 | 英文单词不在词表（随附一份常用英文词表 ~5 万词）且不是专有名词（首字母大写） | 那个词 |
| 字数偏少 | 一页识别字数 < 同任务各页中位数的 50%，且不是最后一页 | 那页 |
| 双重识别 | 上面任何一条命中的页，用第二种方式（另一个提示词或另一个模型，实测后定）再识别；两次逐字比，不一致的片段 | 不一致的片段 |
| 做题反查 | 出答案时模型报"题面不完整 / 选项不成立 / 没有正确选项"（出答案的提示词加一个 `stemProblem` 字段） | 那道题 |
| 手写答案不一致 | 识别到手写答案、且和 AI 答案不同 | 那道题（进 D 的比对） |

#### P3-C4 第三道关：逐页核对
- 路由 `/admin/import/:jobId/review`。一页一屏：上面是这一页识别出的题（按题排，题干、选项可直接改字），**可疑处黄底高亮**、旁边一行原因；
  底部「这页没问题」「这页重拍」。没有可疑处的页显示「本页没有可疑处」+「通过」。
- 页面顶部：「第 3/41 页 · 还剩 6 处可疑」；可只看有可疑处的页。
- 「这页重拍」：拍一张（同 P3-C1 的质检）→ 只重识别这一页 → 替换这一页的题（这一页已改过的字会提示"重拍会覆盖你改过的 2 处"）。
- 每处可疑都要处理（改了 / 点"没问题"）；全部处理完「入库」按钮才可点。
- 入库：一个导入批次写 `exams`、`sections`、`questions`、`question_items`、考点挂接，题目状态草稿、答案「待核」，`answer_source = 'AI'`（有手写答案且一致的记为"已与原书核对"，见 D3）；
  每道题记 `source_page`（印刷页码）和 `edited_fields`（你改过哪些字段）。写入沿用现有上传章节的那套（编号带学科码、可整组删除）。

#### P3-C5 原图的去留
按 BRD 拍板 5「原图一律不保留」。落到实现上有一个前提要你确认（第 12 节待确认 1）：后台排队（拍板 4）和"可疑页再识别一遍"都需要在识别完成之前把压缩后的图暂存。

任务超过 7 天没入库自动放弃，KV 里的图也已过期。入库后哪里都没有图片。图不进 D1 的理由见第 12 节待确认 1。最多同时 60 页 × 约 300KB ≈ 18MB，在 KV 免费额度内。

### 7.2 D 批量核对答案

#### P3-D1 核答案模式
路由 `/admin/bank/:examId/answers`。一题一屏：题面、AI 答案（大字）、AI 的一句理由、出自第 X 页；
两个大按钮「对」「改」；左右滑动 / 按钮切题；「改」展开选项或输入框。手机单手可用（按钮在屏幕下半部）。

#### P3-D2 排序与整组确认
队列顺序：做题反查报了问题的 → 手写 / 答案页比对不一致的 → AI 自己标"拿不准"的（出答案的提示词现在没有这一项，第三期加 `confidence` 字段，和 `stemProblem` 一起出）→ 其余。
"其余"折叠成一行「其余 183 题没有疑点 · 整组确认」。整组确认：对这些题逐题跑标准答案自检（`answerKeyProblems`），通过的确认、不通过的留下并说原因；写审计（依据 = 整组确认）。

#### P3-D3 原书答案页比对
在任务或内容组上「上传答案页」→ 识别出 `题号 → 答案` 列表（同 C 的排队）→ 和 AI 答案逐题比：
一致的标「已与原书核对」并确认（依据 = 原书比对）；不一致的进队列最前，显示两边答案让你选。报告这次的一致率（BRD 成功标准"AI 答案与原书一致率"）。

#### P3-D4 核对单
内容组页「核对单」：拿不准的排前，格式同 `ANSWER_REVIEW.md`；可在页面上看，可下载为 .md。

验收：200 题选择题组 + 答案页，替身下 5 分钟内走完（测试里用脚本点完、量时间只作参考，断的是"一致的全部自动确认、不一致的全部进队列"）。

### 7.3 F 考点整理

路由 `/admin/subjects/:id/knowledge-points`。列表：考点名、上级、挂了多少题、学员掌握度记录数、是否 AI 建的。
- **改名**：同学科不重名（已有唯一约束）。
- **调上下级**：只能挂到本学科的一级考点下，不能挂到自己的下级。
- **合并 A → B**（一个 batch）：`question_knowledge_points` 里 A 改成 B（已同时挂 B 的去重）；`user_knowledge_mastery` 里同一学员同一课程两行相加
  （对、错次数相加；连对取最近练习那一行的；最近练习时间取较晚）；A 的下级改挂 B；删 A；审计记下 A 的全部数据以便追查。
- 不做删除（BRD 第 7 节）。
