# 用自己的服务器做反向代理（2026-11-12）

学员访问 `https://你的域名`，你的服务器（新加坡腾讯云，Ubuntu）替他去 Cloudflare 上的
`https://xlearn.eng1300-79fe2787.workers.dev` 取页面和数据。系统、数据库、部署流程都不动，
Cloudflare 上那个地址也照样能用。

为什么这样能解决"国内电脑打不开"：workers.dev 在国内部分网络下被拦或很慢；新加坡到 Cloudflare 很快，
国内到新加坡腾讯云一般比直连 workers.dev 稳。新加坡的服务器不需要 ICP 备案。

## 一次性的准备（在腾讯云控制台）

1. **安全组**放行 TCP 80、443 入站（申请证书要 80，访问要 443）。
2. **域名解析**加一条 A 记录：`你要用的域名`（比如 `xue.example.com`）→ 服务器的公网 IP。生效通常几分钟。

## 在服务器上跑一次脚本

用 SSH 登录服务器（腾讯云控制台的"登录"按钮也行），复制粘贴这两行：

```bash
curl -fsSL https://raw.githubusercontent.com/tonychenf/Eng1300/main/scripts/proxy/setup-nginx.sh -o setup-nginx.sh
sudo bash setup-nginx.sh 你的域名 你的邮箱
```

它会：装 nginx 和免费证书工具 → 先确认服务器连得上 Cloudflare → 写好 nginx 配置 → 确认域名已经指到这台服务器 →
申请 Let's Encrypt 证书、把 http 自动跳到 https（证书到期前自动续）→ 最后访问一次 `https://你的域名/api/health`。
哪一步不对，它会停下并说清楚，比如"域名现在解析到某某，服务器 IP 是某某"。

脚本最后会打印一串**暗号**。

## 把暗号交给系统

1. 打开 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret。
2. Name 填 `PROXY_SECRET`，Secret 粘贴那串暗号，保存。**不要发在聊天里，也不要写进任何文件提交**（仓库是公开的）。
3. 告诉 Claude，重新部署一次；部署时会把暗号写进 Worker。

暗号是干什么的：登录连错 5 次会锁住"这个账号 + 这个来源 IP"。经代理访问时，Cloudflare 看到的来源全是你的服务器，
不加暗号的话所有人会被算成同一个来源——一个人连错 5 次，这个账号谁也登不进去。代理把真实来源 IP 带过去，
附上暗号；Worker 对得上暗号才信这个 IP，有人绕开代理、自己伪造这两个头不管用。
没加暗号之前网站照样能用，只是有上面这个问题。

## 以后

- **平常什么都不用管**：系统照旧通过 GitHub 部署到 Cloudflare，代理自动拿到新版本。
- **换暗号**：在服务器上带上新暗号重跑脚本 `sudo PROXY_SECRET=新暗号 bash setup-nginx.sh 域名 邮箱`，
  再把 GitHub Secret 改成同一个、重新部署。两边不一致期间，登录锁定退回"所有人算一个来源"，网站不会挂。
- **先看看配置长什么样、不动服务器**：`CONF_OUT=/tmp/xlearn.conf bash setup-nginx.sh 域名`。
- **上传上限** 25 MB（拍照导入一张照片压缩后最多几 MB）；**单个请求最长等 180 秒**（传原书答案页、AI 出答案最长一分半）。
