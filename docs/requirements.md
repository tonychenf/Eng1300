# 英语真题题库与自适应练习系统 — 需求文档 (V0.2 草案，供审阅)

## 0. 文档目的与本次修订说明

本文档基于你上传的《2024年4月高等教育自学考试 英语(二) 试题及答案》(课程代码 00015) 样卷分析真题结构，提出一套"真题题库 + 智能组卷 + 限时作答 + AI 批改与学习分析 + 能力评估"系统的完整需求方案，供你审阅、修改、确认后再进入开发。

**V0.2 相对 V0.1 的修订点**（本次你提出的5点修改）：

1. 题库录入方式从"边做题边解析"改为"**批量预上传 + 预解析 + 预标注考点**"；组卷算法增加"**考点尽量不重复、单卷尽量覆盖更多考点**"的约束。
2. 考试时长确定为 **2 小时 30 分钟（150 分钟）**，不再是待确认项。
3. 系统从"单用户本地存储"升级为"**多用户系统**"：每个用户由后台生成独立用户名/密码登录；新增**后台管理界面**统一管理用户账号；托管方案改为选用对中国大陆访问友好、速度较快的**免费集中托管服务器**方案。
4. AI 接口（用于解读用户答案、与标准答案比对进行分析/批改）改为在**后台**统一配置，而非每个用户各自设置。
5. 新增**超级管理员**角色与权限体系：只有超级管理员能登录后台管理系统，普通用户无法访问后台。

**这是一次架构级别的修订**：系统不再是"纯前端 + 浏览器本地存储"的静态站点，而是变成"前端 + 后端服务 + 数据库 + 用户认证"的完整 Web 应用（详见第 6 节技术方案）。

将样卷渲染为图片逐页解析后，得到如下结构（**该 PDF 没有文字层，是纯图片扫描件**，见第 6.2 节的技术影响）：

| 部分 | 题型 | 题号范围 | 题量 | 每题分值 | 小计 | 形式 |
|---|---|---|---|---|---|---|
| 第一部分 | 阅读判断 (True/False/Not Given) | 1–10 | 10 | 1分 | 10分 | 1篇短文 + 10个判断句，单选A/B/C |
| 第二部分 | 阅读理解选择 | 11–15 | 5 | 2分 | 10分 | 1篇短文 + 5题四选一 |

| 第六部分 | 完形填空（词形变换） | 41–50 | 10 | 1.5分 | 15分 | 1篇短文10空，给出词根，需写出正确形式（主观填空，非选择） |

| **合计** | | | **51题** | | **100分** | 选择题部分(1-40) + 非选择题部分(41-51) |

**关键观察：**
- 这是全国自考统一命题科目的**高度标准化**试卷：题型、题量、分值、每部分对应的分值权重逐年基本固定，这是"根据历史真题的题数结构自动组卷"这一需求得以自动化实现的前提。
- 第1–40题为客观题（可自动判分），第41–51题为主观题（第41–50空需要判断词形变化正误，第51题作文需要 AI 评分）。
- **考试时长：2 小时 30 分钟（150 分钟）**，作为固定模板参数（已确认，见修订点2）。

## 2. 系统总体目标

1. **题库预处理化**：预先批量上传成套真题/练习资料，系统对每道题进行**预解析（结构化抽取）+ 预标注（知识点/考点标签）**，管理员在后台校对确认后统一入库，供之后所有用户抽题使用（而非做题时临时解析）。
2. **智能组卷（考点多样化）**：随机组卷时，在保证题型结构、题量、分值权重与真题一致的前提下，优先让**同一份卷子覆盖尽可能多不同的考点**，同一考点的题目尽量不在同一份卷子中重复出现。
3. **限时作答**：模拟卷统一时长 **150 分钟**，倒计时，时间到自动交卷，支持中途保存/暂停。
4. **自动批改 + AI 讲评**：客观题自动判分；主观题（完形词形、作文）以及所有题目的"答案解读"均调用后台统一配置的 AI 接口，将你的作答与标准答案进行比对分析。
5. **错题分析**：针对每道错题，AI 生成"错误原因分析 + 该考点的记忆要点/知识卡片"，沉淀到"错题本"供复习。
6. **能力评估与预测**：结合历史做题记录（各题型正确率、错题分布、考点掌握度、进步趋势）与全部真题的整体难度分布，评估"如果现在去做一套同类型新卷，预计能得多少分"，输出预测分数区间 + 分项能力雷达图 + AI 定性点评。
7. **多用户与权限体系**：系统支持多个用户各自独立登录、各自积累做题记录和评估；**超级管理员**通过后台管理界面统一创建/管理用户账号、管理题库、配置 AI 接口，普通用户无法访问任何后台管理功能。

## 3. 功能模块详细需求

### 3.1 题库管理模块（后台，仅超级管理员可操作）

- **批量上传**：后台支持一次性上传多份 PDF（历年真题/练习资料）。上传后进入**异步预处理队列**，不阻塞后台其它操作。
- **预解析**：系统自动识别 PDF 是否有文字层：
  - 有文字层 → 直接文本抽取；
  - 无文字层（如本次样卷，纯图片扫描件）→ 将每页渲染成图片，调用后台配置的 AI（需具备图片理解/视觉能力）进行版面解析，输出结构化 JSON（部分、题号、原文、题干、选项、正确答案）。
- **预标注（考点/知识点标签）**：解析完成后，系统调用 AI 对**每一道题**分析并打上考点标签（例如：动词时态、名词性从句、词汇辨析、阅读细节定位、阅读推理、段落大意概括、连贯性/逻辑衔接、写作——观点类/说明类等），支持一题多标签。标签体系建议先由 AI 生成候选标签，管理员在校对时可合并/重命名，逐步沉淀出一套稳定的"考点标签库"，保证同类考点在不同年份/套卷间的标签一致，以便组卷阶段做"考点去重/覆盖最大化"的计算。
- **人工校对与发布**：AI 的解析结果与考点标注**必须**经过后台"校对确认"页面——逐题展示"AI 识别结果 vs 原图片"，管理员可修改文字、选项、答案、考点标签，确认无误后点击"发布"，题目才正式进入可组卷题库（未发布的题目不会被抽到）。
- **题库结构管理**：按"科目 → 年份/月份 → 部分(Section) → 题目(Question)"层级组织；每道题记录所属部分类型、原文段落归属、分值、正确答案、考点标签、（可选）官方解析文本。
- **题库统计**：查看已入库真题套数、各题型题目数量、考点标签分布（哪些考点题目多、哪些考点覆盖不足），为后续补充上传提供参考。

### 3.2 智能组卷模块（随机出题，含考点多样化约束）

- **组卷模板**：以已入库真题的"部分数量、每部分题量、每题分值、题型顺序"为模板（多个版本时取最新一次真题结构为默认模板，或允许手动选择）。
- **抽题策略**：
  1. 按模板每个部分单独从题库对应分类中抽题，保证部分结构与真实考试一致；
  2. **考点多样化优先**：抽题时优先选择"与当前卷面已选题目考点标签重叠最少"的候选题，使**同一份卷子内同一考点尽量只出现一次**，整体覆盖尽可能多不同考点（考点数量不足、必须凑够题量时才允许同考点重复，并在组卷预览中提示）；
  3. 支持"难度"参数（简单/正常/困难/随机），依据该用户历史在对应考点/部分的正确率对候选题目加权抽样；
  4. 避免短期内给同一用户重复抽到同一题（按用户维度记录"最近N次出现过的题目"进行规避）；
  5. 阅读类题目以"篇章"为最小抽取单位（一篇短文 + 其所有子题一起抽取，不能只抽单题打散原文语境，篇章内多道子题的考点各自独立参与多样化计算）。
- **组卷预览**：生成后展示本套卷的题型构成、覆盖的考点列表、总分、时长(150分钟)，确认后进入作答。

### 3.3 限时作答模块

- **倒计时**：固定时长 **150 分钟**，页面顶部常驻倒计时。
- **交互方式**：按题型还原真实作答体验——单选题点选选项、填词补文可拖拽/点选词库、完形填空为文本输入框、作文为多行文本框（含字数统计）。
- **自动交卷**：时间耗尽自动提交并锁定，禁止继续修改；提前完成可手动交卷。
- **断点保存**：意外关闭页面/断网后可恢复未完成的作答进度（服务端保存进度，同一次考试内有效，不受设备更换影响）。

### 3.4 自动判分与 AI 答案解读模块

- **客观题自动判分**（第1–40题：判断题/选择题/搭配题/词库填词）：系统直接比对标准答案，逐题给分，无需 AI。
- **AI 答案解读**（贯穿主观题批改与所有题目讲评）：调用后台统一配置的 AI 接口，将用户作答与标准答案进行比对分析：
  - 第41–50题（词形变换填空）：AI 判断所填单词是否为正确词形，给出对/错及正确答案（可叠加规则校验，如拼写与词性检查）。
  - 第51题（作文）：AI 依据"内容要点覆盖度、语言准确性、词汇丰富度、篇章连贯性、字数要求"等维度评分，输出分数 + 分维度点评 + 修改建议。
  - 客观题也可选择性生成"为什么这个选项对/错"的简要解读，帮助理解而不仅是对答案。
- **成绩单**：交卷后立即生成本次成绩单：各部分得分/满分、总分、正确率、比历史平均的高低。

### 3.5 错题分析与学习要点模块

- 对每道判错（或 AI 判定不完全正确）的题目，自动调用 AI 生成：
  1. **错误原因分析**（词汇量不足/语法点误解/阅读理解偏差/审题失误等，引用原文/选项定位说明"为什么错、正确逻辑是什么"）；
  2. **该考点的记忆要点**（提炼成可复用的知识卡片，关联到第3.1节的考点标签体系）。
- **错题本**：所有错题及分析长期保存（按用户隔离），支持按"考点标签/错误原因/时间"筛选查看，支持"重新只做错题本里的题"这一二次练习模式。
- **知识卡片库**：AI 提炼出的记忆要点去重后汇总成用户个人专属的"知识点卡片集"，可浏览或导出。

### 3.6 能力评估与预测模块

评估"如果现在再做一套同类型新卷，预计能得多少分"，采用**统计模型 + AI 定性评估相结合**的方式：

- **统计层**：基于该用户历史所有考试记录，按题型/部分/考点标签分别计算最近一段时间的正确率与得分趋势（加权最近N次表现，越近权重越高），结合官方真题各部分分值权重，加权推算"预测总分"及各部分预测得分。
- **AI 定性层**：把该用户的历史错题分布、薄弱考点、进步趋势提供给 AI，输出：预测分数区间、当前水平定位、最值得优先补强的2-3个薄弱考点、针对性备考建议。
- **展示**：能力雷达图（按各部分/考点维度）、历史分数趋势折线图、预测分数卡片（统计模型分数 + AI 综合意见）。

### 3.7 AI 接口设置模块（后台，仅超级管理员可配置）

- **全局统一配置**：AI 接口（Base URL、API Key、模型名称、协议类型）在后台由超级管理员统一配置一次，**全站所有用户共用同一套 AI 配置**（普通用户前端不出现任何 API 配置入口，也看不到 Key）。
- **用途覆盖**：该 AI 接口同时服务于——① 题库预解析与考点标注、② 主观题批改、③ 全题型答案解读、④ 错题分析与知识卡片生成、⑤ 能力评估的 AI 定性层。
- **连通性测试**：后台提供"测试连接"按钮，验证 Key 是否有效、能否正常返回结果（含文本与图片两种能力的分别测试，因为题库解析需要视觉能力）。
- **安全性**：API Key 只保存在服务端（数据库中加密存储或使用环境变量/密钥管理服务），**不会**下发到浏览器前端；所有 AI 调用均由后端代理发起，前端只与自己的后端通信。
- **用量统计**：后台展示 AI 调用次数、大致 token 消耗，便于控制成本（尤其题库预解析阶段调用量可能较大）。

### 3.8 历史记录与统计看板（用户端，仅本人可见）

- 用户可查看自己的所有历次模拟考试记录（时间、总分、各部分得分、用时）。
- 统计看板：正确率随时间变化曲线、各题型/考点薄弱环节分布、做题总量统计。
- 数据保存在服务端数据库，与账号绑定，换设备登录同一账号即可看到完整历史（不再依赖浏览器本地存储）。

### 3.9 用户与权限管理模块（新增，对应修订点3、5）

- **角色体系**：
  - **超级管理员（SUPER_ADMIN）**：唯一/极少数账号，只能通过后台入口登录；拥有题库管理（3.1）、AI 接口配置（3.7）、用户账号管理（本节）、全站数据统计的全部权限。普通用户登录入口**无法**访问后台任何路由。
  - **普通用户（USER）**：只能登录做题前端；只能看到和操作自己的做题记录、错题本、能力评估；无法看到其他用户的数据，无法访问题库管理/AI配置/用户管理等后台功能。
- **账号创建方式**：普通用户**不支持自助注册**——由超级管理员在后台为每个用户生成账号（用户名 + 初始密码），登录后用户可自行修改密码。
- **后台用户管理界面**：
  - 用户列表：查看所有普通用户的用户名、创建时间、最近登录时间、启用/禁用状态；
  - 新建用户：填写/系统随机生成用户名与初始密码，创建后展示一次性凭据供管理员转发给对应用户；
  - 重置密码：管理员可为任意普通用户重置密码；
  - 启用/禁用账号：禁用后该用户无法登录，但历史数据保留。
- **超级管理员账号**：系统首次部署时通过初始化脚本/环境变量创建唯一的超级管理员账号（用户名与初始密码由部署时设置，建议首次登录后强制修改密码）；不提供"忘记密码自助找回"入口，避免被恶意利用，找回方式为重新运行初始化脚本或直接操作数据库（细节见第9节待确认问题）。
- **登录安全**：密码加盐哈希存储（不明文保存）；登录态使用 Session/JWT，设置合理过期时间；后台管理路由与普通用户路由在权限校验层面严格隔离（同一次登录的 Token 中带角色信息，后端每次请求校验角色）。

```
AnswerRecord { attemptId, questionId, userAnswer, isCorrect, aiJudged(bool), aiScore, aiComment }
WrongItem    { userId, questionId, attemptId, errorAnalysis, memoryPoint, tags[], createdAt }
Assessment   { userId, generatedAt, statPredictedScore, aiPredictedRange, weakPoints[], suggestions }

AISettings   { baseUrl, apiKey(服务端加密存储), model, protocol, visionModel }  // 仅后台可读写，全局唯一一条记录
```

## 5. 界面/页面清单（草案）

**用户端（普通用户）：**
1. **登录页**：用户名 + 密码登录（无注册入口）。
2. **开始练习页**：选择"随机组卷"参数（难度倾向）→ 生成预览（含考点覆盖列表）→ 开始作答。
3. **答题页**：分题型渲染 + 150分钟倒计时 + 进度条 + 交卷按钮。
4. **成绩报告页**：本次得分总览 + 逐题对错 + AI 批改与答案解读详情。
5. **错题本页**：错题列表、筛选（按考点/时间/错误原因）、二次练习入口、知识卡片浏览。
6. **能力评估页**：预测分数、能力雷达图、历史趋势图、AI 备考建议。
7. **个人设置页**：修改密码。

**后台（仅超级管理员）：**

## 6. 非功能需求与技术方案建议

### 6.1 架构总览（相对 V0.1 的重大变化）

V0.1 原方案为"纯前端 SPA + 浏览器本地存储"，因新增多用户登录、后台管理、AI Key 服务端保密等需求，**必须引入后端服务与数据库**，架构调整为：

```
前端 (用户端 SPA + 后台管理 SPA)
        │  HTTPS API 请求
        ▼
后端服务 (鉴权 / 业务逻辑 / AI 代理转发)
        │
        ├─ 数据库 (用户、题库、做题记录、AI配置)
        └─ 转发调用 → 你提供的 AI API
```

前端不再直接持有 AI Key，也不再是"每用户本地存储各自数据"，而是所有数据集中存储在后端数据库，按 userId 隔离。

### 6.2 PDF 解析的技术约束（沿用 V0.1 结论）

经检测，本次样卷 PDF **不含文字层**（`pdftotext` 提取结果为空），是排版后转图片/扫描类型的 PDF：
- 常规文本提取对这批真题完全无效，必须走"页面转图片 + AI 视觉模型解析"路线；
- 若后续导入的其它 PDF 是可选中文字的普通 PDF，系统自动识别并直接走文本抽取（更快更准，无需消耗 AI 调用）。

### 6.3 技术栈与免费托管方案建议

- **前端**：React + TypeScript + Vite；Tailwind CSS；图表用 Recharts。
- **后端 + 数据库 + 托管三合一建议：Cloudflare 全家桶**
  - **Cloudflare Pages**：托管前端静态资源；
  - **Cloudflare Pages Functions / Workers**：承载后端 API（鉴权、业务逻辑、AI 代理转发）；
  - **Cloudflare D1**（基于 SQLite 的免费托管数据库）：存储用户、题库、做题记录等数据；
  - 免费额度对个人/小规模多用户场景完全够用，且部署、域名、HTTPS 均在同一账号内一站式管理。
  - **关于"中国大陆友好"的现实说明**：目前没有哪个海外免费平台能保证在中国大陆 100% 稳定快速访问（GFW 环境下 Vercel / Netlify / GitHub Pages 都可能出现间歇性变慢或超时）。综合比较，**Cloudflare 的全球节点在国内的可达性和速度通常相对更好**（不少国内开发者也用它做免费的国内可访问服务），是免费方案里的相对最优解，但仍建议做好"偶尔访问较慢"的心理预期。如果之后对国内访问稳定性要求进一步提高，**唯一可靠的路径是升级为付费的国内云服务器（阿里云/腾讯云）并完成域名备案**，这个方案不再免费，是否需要预留升级路径请在第9节确认。
- **鉴权**：JWT 或服务端 Session，密码使用 bcrypt/argon2 加盐哈希存储。
- **AI 调用**：后端统一代理转发到你配置的 AI API（默认按 OpenAI Chat Completions 兼容协议对接，如你的 API 协议不同需另行提供接口文档，见第9节）。

### 6.4 其它非功能需求

- 响应式布局，桌面端与移动端浏览器均可用。
- AI 调用失败（网络错误/Key 无效/超额度）需有清晰报错提示，且不能影响客观题判分和数据保存的核心流程。
- 数据隔离：任何 API 都必须校验当前登录用户身份，普通用户之间的数据严格隔离，普通用户无法通过接口越权访问后台数据。
- 数据备份：后台提供题库与核心数据的导出能力，防止误操作导致数据丢失。
