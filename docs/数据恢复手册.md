# 数据恢复手册（CR-M6）

数据坏了、丢了，照这一页做。所有操作都在 GitHub 网页上点：仓库 → **Actions** → 左边选流水线 → **Run workflow**。
不需要在自己电脑上装任何东西。

> 先别急着部署。库出了问题时再推送一次，可能把现场盖掉。

## 一、先判断走哪条路

| 情况 | 走哪条路 | 会丢什么 |
|---|---|---|
| 7 天之内坏的（一次部署把数据弄坏了、误删了一批记录……） | **二、时间旅行**：整库回滚到坏之前 | 恢复点之后的**一切**写入 |
| 超过 7 天才发现；或者库被删了 / 换了账号 | **三、从加密备份恢复**：把某次部署前存的备份导进一个新库，再切过去 | 那份备份之后的一切写入 |
| 部署红在「找不到数据库」 | **四** | — |

时间旅行是 Cloudflare D1 自带的：免费版能回到 **7 天内**任何时刻（付费版 30 天）。每个库 10 分钟内最多恢复 10 次。

加密备份是每次部署在动库之前做的整库导出，存成那次部署运行的附件，**留 90 天**。

## 二、时间旅行：整库回滚到某个时间点（7 天内）

1. **找时间点。** 两种填法，任选：
   - **书签**：哪次部署把数据弄坏了，就打开那次部署的运行页，摘要里有「部署前的恢复点」，复制那串书签。
     这是最准的，正好回到那次部署动库之前。
   - **北京时间**：直接写 `2026-10-01 15:00`（按北京时间理解，不用自己换算）。
     也可以写 `2026-10-01T07:00:00Z`（世界时）或 Unix 秒。
2. Actions → **Restore XLearn database** → Run workflow：
   - 恢复方式：`time-travel`
   - point：上面的书签或时间
   - confirm：填线上库名 `xlearn`（防手滑；填错了什么都不会动）
3. 流水线会依次：
   1. 核对输入，打出"按北京时间几点理解"；
   2. 记下**撤销书签**；
   3. 整库恢复；
   4. 补齐表结构（和部署里那几步一样，只补不删）；
   5. 列出恢复前后行数有变化的表。
4. **恢复错了？** 日志最后一行「撤销：……时间点填 xxx」，拿那个书签再跑一次就回到恢复前。
5. **做完之后**，手动触发一次部署（Actions → Deploy XLearn worker → Run workflow）。
   它会把恢复点之后新加的题库文件导进来，再跑一遍线上验证。

**会丢什么**：恢复点之后的一切写入，整库回去，不能挑表。具体是：
- 学员的作答、错题、掌握度；
- 后台确认过的答案、改过的题面、停用的题、发布和撤回；
- 授权变更、AI 配置；
- 上传的内容；
- 登录记录。

## 三、从加密备份恢复（超过 7 天，或库没了）

1. **找备份。** Actions → Deploy XLearn worker，找一次**出事之前**的部署运行，点进去。
   - 页面最下面 Artifacts 里有 `d1-backup-<运行编号>-<次数>`；
   - 浏览器地址栏 `runs/` 后面那串数字就是**运行编号**。
2. Actions → **Restore XLearn database** → Run workflow：
   - 恢复方式：`backup`
   - backup_run_id：上面的运行编号
   - new_db_name：新库名，例如 `xlearn-restored-20261001`（不能是线上库名 `xlearn`）
   - confirm：再填一遍新库名
3. 流水线会：
   1. 下载那份备份；
   2. 新建库；
   3. 用 Secret `BACKUP_PASSPHRASE` 解密、导入；
   4. 做三道核对：
      - 每张表行数和备份一致；
      - 导进去再导出来，数据逐行一致；
      - 容易被导出写走样的文本逐个核对原样。
   
   **线上库不碰。**
4. **切过去**：把 `worker/wrangler.toml` 里的 `database_name` 改成新库名，推送（让 Claude 改也行）。
   部署会找到新库、把站点绑上去。整个流水线的库名只认这一行。
5. 旧库留着查原因。确认用不着了，再到 Cloudflare 后台手动删——自动化里唯一能删库的脚本只删演练用的一次性库。

**口令丢了，备份就打不开。** `BACKUP_PASSPHRASE` 存进 GitHub 就读不回来，所以要另存一份（密码管理器）。

自己电脑上想看备份内容，可以手动解密：

```bash
gpg --decrypt --output dump.sql xlearn-YYYYMMDD-HHMMSS.sql.gpg
```

## 四、部署红在「找不到数据库」

部署找不到库时，**不再自动新建**，直接停下，什么都不动（CR-M15）。

以前会悄悄建一个空库顶上：导题库、建账号，线上验证照样全绿，学员数据却全没了。

- **真是第一次上线**：手动触发部署，勾上「首次部署，允许新建数据库」。
- **其余情况**（库被删了、API Token 换到了别的账号）：先别部署，按**三**从备份恢复。

## 五、恢复演练

Actions → **D1 recovery drill**，在一次性的库（`xlearn-drill-<运行编号>-*`）上把二、三两条路真走一遍，跑完删库。

- 改了恢复相关的脚本，推送时会自动跑一次；
- 平时可以每个月手动跑一次，勾上「真实备份」：把最近一份线上备份导进一次性库核对，证明备份真的恢复得了；
- 不勾占约一千行写入额度，勾了约等于线上整库的行数；
- 不调 AI，不花钱。

演练 #1（2026-10-01）实测：
- 一次时间旅行恢复约 2 秒；
- 演练库约 230 行，导出 3 秒、导进新库 3 秒，整轮演练约 4 分钟（其中两段各等 65 秒）；
- 书签长这样：`00000000-00000092-000050f7-9e79038ba5c5cdce4a2a9102eaf0db1f`。

演练 #5（2026-10-02，勾了真实备份）：线上那份备份（32 张表、2999 行、明文 1372 KB）按先父后子重排后导进一次性库，
3 秒导完，三道核对全过。重排之前原样导不进去，原因见下面"导出的顺序"。

## 六、几件要知道的事

- **公开仓库**：
  - 流水线附件登录 GitHub 的人都能下，所以备份只存密文；
  - 线上导出时 wrangler 会把整库的下载链接（一小时有效）打进日志，备份脚本把这段输出藏了起来。
- **导出时会卡几秒**：D1 导出期间会挡住这个库的其他请求，库小只有几秒。部署时做一次。
- **导出的顺序**（2026-10-02 演练照出）：
  - 现象：线上的备份原样导不进新库，D1 只回 `{"D1_RESET_DO":true}`。
  - 原因：导出按建表顺序写。线上库早先拆掉重建过题目表和考点表，它们排到了作答、错题这些子表后面，备份里子表的数据就在父表还没建的时候先插，外键对不上，整个导入回滚。新建的库父表总在前面，所以演练库从来碰不到。
  - 处理：恢复时先把建表语句全放最前、数据按外键先父后子重排再导（自动的，不用操心）。备份文件本身不动，以前存的备份照样能恢复。
  - 导不进去时，演练会接着打印一份诊断：只有表名、条数、字节数，没有数据。
- **导出器的一个毛病**：
  - 现象：导出器把文本里的换行写成 `\n`。同一段文字里要是本来就有字面的 `\n`（公式里的 `\nu`、`\neq`），导回去会一起变成换行。
  - 处理：备份时把这种文本找出来按原样补在备份末尾，导入后逐个核对。
  - 记录：`manifest.json` 的 `fixups` 记着补了几处。
- **后台的两个 JSON 导出只供查看，不能拿来恢复**（后台 → 数据导出）：
  - 题库导出只有章节、题目、考点名、存疑；
  - 作答导出只有作答、答题、错题、掌握度；
  - 32 张表只导了 10 张，账号、授权、得分单元、图片、AI 配置等都没有。
  - 恢复用的是部署时做的整库备份。
