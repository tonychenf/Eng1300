# 改进阶段 2：后台自助开学科 — 需求文档

> **状态：待用户审阅（2026-11-07 起草）。审阅通过之前不动代码。**
> 每一项末尾有「待你拍板」，带我的推荐；文末有汇总表。你逐条回复「同意推荐」或改成别的选项即可。

## 0. 背景与目标

开「公共英语」时，学科、课程、题型、组卷模板全靠迁移 0018 写进库，题面是 Claude 逐页看扫描件转写的——
每开一个学科都要改代码、走 PR、部署一次。用户的预期是"后台上传试题，AI 自动出答案、拆题、拆考点"。

**本阶段的目标（一句话验收）**：管理员手里有一份新课程的资料（Word、PDF 或拍照），**不改代码、不部署**，
在后台完成：建学科 → 配题型和组卷 → 上传资料 → AI 拆题、出答案、拆考点 → 校对 → 发布 → 开通学员，
学员当天就能练习、能考模考。

## 1. 现状盘点（2026-11-07 读代码确认）

| 环节 | 现在 | 问题 |
|---|---|---|
| 建学科 | 后台「学科管理」能建（学科码、名称、内容组织方式） | 建出来的学科**什么都没有**：没有课程、没有题型、没有评价标准、没有组卷模板。能力包读不出来（`subject_rubric_missing`），上传报"名下还没有课程" |
| 题型、评价标准、提示词、参数 | 后台「能力包」页能改 | 要从零手填 JSON 一样的配置，没有参照；提示词没配的走全局兜底 |
| 课程 | **只能靠迁移建** | 后台看不到、改不了课程的满分和时长 |
| 组卷模板 | **只能靠迁移写**（生化 0017、公共英语 0018） | 后台连看都看不到；没有模板就组不出模考卷 |
| 上传资料 | 只有一条管线：Word（`docx-structured`） | **只认生化习题的版式**：按「填空题 / 选择题 / 名词解释 / 问答题」四个标题切大题、映射到四个固定题型码。换一个学科的 Word，标题不一样就切不出题；英语那样带篇章的题（阅读、段落填空）完全不认 |
| 上传页选课程 | 没有课程选择 | 一个学科有两门以上课程时，上传直接报 `course_required` |
| 扫描件 / 图片 | 不支持 | 平台里已经有读图的底子：AI 配置预留了「图片解析 AI」一档（`PARSING`，带"能读图"标记），`lib/ai.js` 有 `ocrImage`，但没有任何管线用它 |
| AI 出答案、采分点、考点 | 有（`/exams/:id/ai-answers`），上传后自动跑，并发、分批、可重跑 | 可以直接复用 |
| 校对、确认、发布、开通学员 | 有 | 可以直接复用 |

所以原计划的三项要扩一点：**A 不只是建课程，是"建一个能用的学科"；C 不只是扫描件，是"不挑版式的 AI 拆题"**，
Word 也走它。

## A. 新建学科开箱可用（课程 + 能力包一次建好）

### A1. 用户故事

管理员在「学科管理」点「新建学科」，填学科码、名称，选一个**参照学科**（比如"公共英语"），点保存。
得到的新学科马上就有一门课程、一套题型、评价标准、提示词，可以直接去上传资料；要调整再去能力包页改。

### A2. 功能

1. **建学科时一并建课程**：
   - 表单多三项：课程名称（默认 = 学科名）、满分（默认 100）、考试时长（分钟，默认 120）；
   - 课程码自动生成 `<学科码>-main`，不让手填（课程码进 URL、进题号，填错了改不了）；
   - 学科行和课程行在**同一个 batch** 里落库：不会出现"学科建了、课程没建"的半成品。
2. **参照学科复制能力包**（可选，默认"不参照"时用一套通用默认值）：
   - 复制：题型声明、生效中的评价标准、四类提示词、学科参数覆盖；
   - **不复制**：题目、考点、组卷模板（模板要按新学科的题量重新配，见 B）、学员授权；
   - 提示词里写死的学科名（"你是一位生物化学……老师"）复制时替换成新学科名；替换不掉的（管理员自己改过的措辞）原样复制，
     页面上提示"提示词里可能还有原学科的说法，请到能力包页检查"。
   - 通用默认值（不参照时）：单项选择、填空（精确比对）、简答（按采分点 AI 批改）三种题型；评价标准与生化同一套口径
     （给部分分、掌握度阈值）；提示词用全局兜底那份。
3. **课程管理**：学科管理页每个学科下列出它的课程，可改名称、满分、时长；可以给一个学科**加第二门课**
   （课程码 `<学科码>-<自定后缀>`）。不提供删除课程（课程下挂着题和学员记录）。
4. **上传页选课程**：学科有多门课程时，上传页多一个"挂到哪门课"的下拉；只有一门时不显示、自动用它。
5. **老学科补课程**：已有学科没有课程的（理论上现在没有，防后台建过的），学科管理页显示"补建课程"按钮。

### A3. 接口（草案）

- `POST /api/admin/subjects`：请求体加 `course: { name, totalScore, timeLimitMinutes }`、`copyPackFrom: <学科码 | null>`；
  学科码已占用 409、参照学科不存在 404、满分 / 时长不是正数 400；
- `GET /api/admin/subjects/:id/courses`、`POST /api/admin/subjects/:id/courses`、`PATCH /api/admin/courses/:courseCode`；
- 全部只限超级管理员；建学科、改课程写审计（谁、什么时候、改了什么）。

### A4. 规则与边界

- 改课程满分只影响**以后组的卷**；已交的卷、成绩报告不变（卷面分值在组卷那一刻就写进了作答记录）。
- 改满分之后，现有组卷模板的分值加起来可能对不上新满分：保存课程时**提示**"组卷模板总分 X，与新满分 Y 不一致，请去改模板"，
  不自动改模板（B 里组卷前会再拦一次）。
- 学科码规则照旧（小写字母开头、2–20 位）；建了不能改。

### A5. 验收

- 后台新建学科（参照公共英语）→ 不碰代码 → 能力包页看得到复制来的题型 → 上传页能选到它 → 上传成功；
- 新建学科（不参照）→ 能力包读得出来（不再 `subject_rubric_missing`）；
- 测试：`n1-subjects`、`n3-pack`、`n6b-upload` 加断言；建学科的半成品场景（课程写失败）整体回滚。

### A6. 待你拍板

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| A-1 | 新学科没有参照时用什么默认题型 | ①单选 + 填空 + 简答三种通用的 ②一个都不给，逼管理员自己配 | ① |
| A-2 | 要不要支持一个学科多门课 | ①支持（加第二门课）②一个学科只一门课 | ①（英语就是两门课合成一门的，以后可能还有） |

## B. 后台编辑组卷模板

### B1. 用户故事

管理员在某门课的「组卷模板」页，照着纸质试卷的说明，一行一行配："拼写单词，从【拼写单词】题型里抽 20 题，每题 0.5 分"……
保存时系统检查分值加起来对不对，并马上告诉他"按现在已发布的题，每一部分凑不凑得够"。

### B2. 功能

1. **模板编辑页**：入口在学科管理页的课程行上（「组卷模板」按钮）。表格每一行是一个部分（模板项）：

   | 列 | 说明 |
   |---|---|
   | 顺序 | 拖动或上下移，决定卷面上的先后 |
   | 部分名称 | 卷面上显示的大题名，如"阅读理解（一）" |
   | 从哪些题里抽 | 多选：按**题型**（单项选择、拼写单词……）和 / 或按**大题类型**（选择填空、阅读理解……，即上传时切出来的大题名）；可选再加考点、难度。多个条件取交集 |
   | 抽几题 | 正整数 |
   | 每题几分 | 正数，可以是 0.5 |
   | 抽题方式 | 「按题抽」（选择、填空这类单独成立的题）或「整篇抽」（阅读、完形这类带篇章的，一篇的题全上，篇章题量必须正好等于"抽几题"） |

   下拉里的备选从库里现取：本学科声明的题型、本课程已有的大题类型，不让手打（手打错一个字就永远抽不到）。
2. **保存时的校验**（不通过就拒绝保存，并说清是哪一行、为什么）：
   - 每行至少一个筛选条件；题型必须是本学科声明过的；
   - 抽几题、每题分值是正数；整篇抽的那一行只能按大题类型筛（按题型筛整篇抽没有意义）；
   - **各部分分值之和必须等于课程满分**（见 B-1）；
   - 部分名称不能重复。
3. **保存后立即体检**：调现有的 `exam-readiness`，每一行显示"可选 N 篇 / N 题，需要 M"，凑不够的标红并说差多少。
   体检只是提示（题还没发布完是正常状态），不拦保存。
4. **只影响以后组的卷**：已组的卷、进行中的考试、历史成绩不受影响。
5. **一门课一份模板，整体保存**：两个人同时改时，后保存的人会被拒（"模板已被 X 在 HH:MM 改过，请刷新"），不静默覆盖。

### B3. 接口（草案）

- `GET /api/admin/courses/:courseCode/template` → `{ items, updatedAt, updatedBy, readiness }`；
- `PUT /api/admin/courses/:courseCode/template`，请求体 `{ items, baseUpdatedAt }`：整体替换（一个 batch 先删后插），
  `baseUpdatedAt` 对不上回 409；校验不过 422 并列出每一行的问题；
- 和迁移的关系：迁移里装模板的那几段已经带门闩（0017、0018），后台改过之后部署不会冲回去——这一点有测试守着。

### B4. 验收

- 新学科（A 建的）配好模板、发布题目之后，学员能组卷，卷面结构、总分与模板一致；
- 分值对不上满分、题型没声明、整篇抽却按题型筛：保存被拒且说清原因；
- 后台改了公共英语的模板 → 再部署一次 → 模板还是改过的样子（`deploy-local` 加一段）；
- 浏览器测试：三种宽度下能增删行、能保存、能看到体检结果。

### B5. 待你拍板

| # | 问题 | 选项 | 推荐 |
|---|---|---|---|
| B-1 | 各部分分值之和 ≠ 课程满分时 | ①拒绝保存 ②允许保存、只警告 | ①（总分不对，学员看到的成绩就是错的） |
| B-2 | 编辑入口放哪 | ①学科管理页的课程行上 ②能力包页里 | ①（模板跟课程走，不跟学科走） |

## C. AI 拆题导入：Word / PDF / 图片，不挑版式

### C1. 用户故事

管理员在上传页选学科、选课程，拖进一份资料——可以是 Word、文字版 PDF、扫描版 PDF，或者手机拍的一组照片。
系统逐页识别文字，再由 AI 按**本学科声明的题型**拆成大题、篇章、题目、选项，给出预览；管理员看一眼、确认入库，
后面照旧自动出答案、拆采分点、挂考点，进校对页。公共英语那份扫描件，以后就这么传，缺的 141–153 页拍照补上即可。

### C2. 流程

```
选文件 ─► 浏览器里拆页、压缩成图片（PDF / 照片）
          或抽出全文（Word、文字版 PDF）
     ─► ① 识别：逐页把图片交给「图片解析 AI」读出文字（Word 跳过这一步）
     ─► ② 拆题：把整份文字交给「文本解析 AI」，按本学科题型声明拆成大题 / 篇章 / 题目 / 选项
     ─► ③ 预览：大题数、每类题数、存疑的地方；可以改内容组名称、排序；不满意可以重拆
     ─► ④ 入库（和现在的上传同一套落库、同一套"拿不准就拒"的检查）
     ─► ⑤ 自动出答案、采分点、考点（现有接口，原样复用）
     ─► ⑥ 校对 → 确认 → 发布（现有）
```

### C3. 关键设计

1. **逐页、由浏览器驱动**：一页一个请求，页面上有进度条（"识别第 12/41 页"），失败的页单独重试，关了页面能从断点接着做。
   不在一个请求里跑完整份：41 页 × 每页十几秒，一个请求扛不住，也没法看进度。
2. **识别和拆题分两步、两档模型**：读图贵，只用在"图 → 文字"；拆题是纯文字，用便宜的文本模型。两档在「AI 配置」页分别配
   （已有的 `PARSING` 与 `TEXT_PARSING`）。
3. **拆题按整份文字做，不按页**：题目、篇章经常跨页（公共英语第 185 题就跨了页）。文字太长时按大题边界分批送。
4. **按学科题型拆**：拆题的提示里带上本学科声明的题型（名称、作答形态、判分方式），AI 只能从里面选；
   选不出来的题不丢，记成「解析存疑」，在预览和校对页点名。
5. **篇章题**：阅读、段落填空这类，AI 要把篇章原文和它下面的题挂在一起（和英语题库同一种结构），段落填空的词库照原样保留。
6. **结果一律待校对**：拆出来的题落库是「草稿 + 缺答案」，出答案之后是「待核」，和现在的上传一样，
   人不确认就发布不了、学员看不到。
7. **Word 也走这条路**：现有的 Word 管线（只认生化版式）保留不删，作为生化专用；其他学科的 Word 走 AI 拆题。
   上传页按文件类型自动选，不用管理员懂管线。
8. **手写答案**（你发来的照片里那种）：识别时顺带读出题号旁边手写的答案字母，作为**候选答案**（来源标"手写识别"、待核），
   AI 出答案时以它为准、不一致的标出来。见 C-4。

### C4. 原件保存（与现在的规矩冲突，要你定）

现在的规矩是**原件不落盘**（上传接口只留抽出来的文字，你当时选的）。但扫描件校对时，最需要的就是**对照原图**看识别对不对。

| 方案 | 怎么做 | 代价 |
|---|---|---|
| ①不存图（保持现规矩） | 只留识别出的文字；每道题记下"出自第几页"，校对时你对照手边的纸本 | 零成本；校对页看不到原图 |
| ②存页面图片 | 每页压成 JPEG（约 200–400KB）存进 Cloudflare R2 对象存储；校对页每道题旁边能点开它所在的那一页 | 要在你的 Cloudflare 账号里开 R2（免费额度 10GB，公共英语那份约 15MB）；仓库是公开的，图片只经后台接口、要登录才看得到 |
| ③存缩略图进 D1 | 压到很小存进数据库 | 不推荐：D1 有单行和总量上限，图太糊对照意义不大 |

### C5. 模型选型与成本（先实测、你拍板，再写管线）

- 候选：硅基流动上的视觉模型（Qwen 视觉系列等，和现在用的同一个服务商、同一把 Key），以及你指定的其他服务商；
- **实测怎么做**：本机连不到 AI 服务商，所以加一条只手动触发的流水线（类似 `ai-smoke-test`），
  拿公共英语扫描件里有代表性的 5 页（纯选择题页、两栏选项页、阅读篇章页、教学重点中英对照页、你拍的带手写答案的照片）
  跑识别 + 拆题，和我已经人工转写好的版本逐字比对，报出：每页准确率、错在哪类地方、每页耗时、每页花费；
- 实测花费估计在几毛钱以内；**跑之前我会先告诉你预计花多少，你同意再跑**；
- 选型结果写进本文档，你定了用哪个模型再开工。

### C6. 规模与限制

- 单次上传：PDF 最多 60 页、图片最多 60 张、单张照片自动压到长边 1600 像素；超了提示分批传；
- 每页识别并发 3（服务商限速内）；预计 40 页一份 5–10 分钟（以实测为准）；
- 拆题失败、识别失败都可单页 / 单批重试，已成功的不重跑、不重复花钱。

### C7. 前端依赖（与现在的规矩冲突，要你定）

浏览器里把 PDF 拆成页面图片，需要引入 **pdf.js**（Mozilla 的 PDF 渲染库，约 1MB，只在上传页按需加载、学员端不加载）。
现在的规矩是"KaTeX 是唯一引入的前端库"。不引的话只能让你先把 PDF 自己转成图片再传。

### C8. 验收

- 把公共英语扫描件的若干页（含两栏选项、跨页题、阅读篇章、段落填空）传上去：拆出的题数、大题、篇章挂接正确，
  识别错误在预览 / 校对页能看出来、能改；
- 一份非生化版式的 Word 传上去能拆出题；生化那份 Word 照旧走原管线、结果不变；
- 带手写答案的照片：候选答案读得出来，进校对页是待核；
- 本地测试用替身模拟两档模型（含"识别出乱码""拆题返回形状不对""某页超时"这些情况）；
  **替身证明不了识别准确**，上线前用 C5 那条流水线对真模型跑一遍；
- 浏览器测试：三种宽度下能选文件、看进度、重试失败页、看预览。
