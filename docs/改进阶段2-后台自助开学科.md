# 改进阶段 2：后台自助开学科（不再靠迁移 + 部署）

> 2026-11-07 用户提出、确认排进下一阶段。起因：开「公共英语」时，学科、课程、题型、组卷模板全靠迁移 0018 写进库，
> 题面是 Claude 逐页看扫描件转写的——每开一个学科都要改代码、走 PR、部署一次。
> 用户的预期是"后台上传试题，AI 出答案、拆题、拆考点"，这条链路已经有一半（docx 上传 + AI 出答案、采分点、考点），
> 缺的是下面三项。

## 现状：后台已经能做的

| 环节 | 在哪 | 状态 |
|---|---|---|
| 建学科 | 后台「学科管理」（`POST /api/admin/subjects`） | 有 |
| 题型、评价标准、AI 提示词、参数 | 后台「能力包」（`/api/admin/subjects/:id/pack/*`） | 有 |
| 上传题库 → AI 出答案、拆采分点、给考点 | 后台上传（`POST /api/admin/bank/import`、`/exams/:id/ai-answers`） | **只认 docx**（`docx-structured` 一条管线） |
| 校对、确认、发布 | 后台校对页 | 有 |
| 开通学员 | 后台授权 | 有 |

## 要补的三项

### A. 后台建学科时一并建课程（小）

**问题**：后台建出来的学科没有课程，上传时报 `no_course_for_subject`「名下还没有课程，题没有地方挂」。课程行现在只能靠迁移建
（生化 0013、公共英语 0018）。

**做法**：
- 建学科接口带上课程（课程码默认 `<学科码>-main`、名称、满分、时长），学科行和课程行一个 batch 落库；
- 学科管理页加课程的显示与编辑（名称、满分、时长）；已有学科没有课程的，页面上给"补建课程"的入口。

**验收**：后台新建学科后不碰代码就能上传 docx；`n1-subjects` / `n6b-upload` 加断言：新建学科 → 有课程 → 上传成功。

### B. 后台编辑组卷模板（中）

**问题**：没有模板就组不出模考卷（只能练习）。模板现在只能靠迁移写（生化 0017、公共英语 0018），后台连看都看不到。

**做法**：
- 接口：读、整体替换某门课的 `exam_template_items`（标签、筛选条件——题型 / 大题类型、题数、每题分值、按题抽还是整篇抽）；
- 保存前校验：筛选条件认得出（`template-filter.js`）、分值加起来等于课程满分、题型都在能力包里声明过；
- 页面：在学科管理或能力包页加「组卷模板」一栏，保存后直接显示 `exam-readiness`（每一项现在凑不凑得够）；
- 迁移里的模板照旧带门闩：后台改过的，部署不冲回去。

**验收**：后台给一个新学科配好模板 → 学员能组卷；分值对不上、题型没声明时保存被拒并说清原因；`bio-exam` 那类期望值改成从库里现算。

### C. 上传扫描件 / 图片（大）

**问题**：上传只实现了 docx 一条管线（按生化习题的版式写的）。扫描 PDF、拍照的卷子传不进来；平台自己的 AI 配置里
「教学」「文本解析」是文本模型，读不了图。公共英语就是卡在这里，最后由 Claude 看图转写。

**做法**（要先定的事在最前面）：
1. **选读图的模型**：后台 AI 配置里已经预留了「图片解析 AI」（`PARSING`），要选一个能看图的服务商和模型，
   先用公共英语的几页扫描件实测识别准确率和每页成本，再定。**这一步要用户拍板（花钱）**；
2. 新管线 `pdf-ocr-llm`（`worker/src/import/index.js` 里已留了位置）：PDF 拆页 → 每页图片交给读图模型 → 输出和 docx 管线
   同一种结构（大题、题干、选项、篇章），之后走现有的 AI 出答案、拆采分点、考点、校对、发布；
3. Worker 的限制要先摸清：单次请求的 CPU 时间、请求体大小（现在上传上限 10MB，公共英语那份是 16MB）、
   拆 PDF 在 Worker 里做还是前端做；
4. 识别结果必然有错：校对页要能对照原图（每页图存下来，题目记住出自哪一页）。

**验收**：把公共英语那份扫描件（或其中几页）传上去，题面识别出来、进校对页、能对照原图改、确认后发布。

## 顺带
