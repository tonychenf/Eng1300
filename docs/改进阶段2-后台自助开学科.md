## 0. 背景、使用者、目标

**背景**：开「公共英语」时，学科、课程、题型、组卷模板全靠迁移 0018 写进库，题面是 Claude 逐页看扫描件转写的，
答案也是 Claude 预填、再由你整批确认的——每开一门课都要改代码、走 PR、部署一次，还要有人在聊天里一步步提醒还差什么。

**使用者**：

| 谁 | 特点 | 这一阶段对他们意味着什么 |
|---|---|---|
| 管理员（你） | 唯一的管理员；**主要用手机**（拍照、在聊天里发图片）；不写代码 | 能自己开课、传资料、核答案、上线 |
| 学员 | 手机为主；按学科开通 | 新课上线当天就能练、能考；练习里每种题都有有用的反馈 |

**目标（一句话）**：你手里有一门新课的资料（Word、PDF、拍照都行），**不改代码、不部署、全程在手机上**，
完成建课 → 传资料 → 核答案 → 配组卷 → 发布 → 开通学员，学员当天能用。

### 成功标准（上线后按这几条判断这一阶段做得好不好）

| 指标 | 现在（公共英语那次） | 目标 |
|---|---|---|
| 开一门新课你要花的时间 | 约一天的开发 + 一次部署 + 多轮聊天确认 | 后台操作 2 小时以内（40 页资料量级），不需要我参与 |
| 题目完整率（每道题都识别出来、题号连续、选项齐全） | —（人工转写） | **100%**：缺题、缺选项一律在体检里拦下，不进库 |
| 印刷体字符准确率（识别结果和原书逐字比） | —（人工转写） | **≥ 99.5%**（约每页错 1–3 个字），由 C 的选型实测证明；达不到这个门槛 C 不上线 |
| 进库前被人看过的可疑处 | — | 体检标出的可疑处 **100%** 在你手里拿着书的时候核过 |
| 核答案的工作量 | 400 道题靠文件整批确认，后台逐题点不现实 | 只看"有问题的题"；其余整组确认；有原书答案页时自动比对、只看不一致的 |
| AI 答案与原书答案一致率 | 第二组前 75 题 74 题一致（98.7%） | 作为基准持续记录，每次有原书答案页时报出来 |
| 每页识别花费 / 每月 AI 总花费 | — | 实测后给出每页花费；每月总额有上限，超了停下等你确认 |
| 上线后漏做的事 | 部署完要我告诉你"还差确认 32 题、发布、开通学员" | 后台的上线清单直接列出，零遗漏 |

## 1. 现状盘点（2026-11-07 读代码 + 浏览器实测）

| 环节 | 现在 | 问题 |
|---|---|---|
| 建学科 | 后台「学科管理」能建 | 建出来**什么都没有**：没有课程、题型、评价标准、组卷模板；能力包读不出来（`subject_rubric_missing`），上传报"名下还没有课程" |
| 能力包（题型、评价标准、提示词） | 后台能改 | 评价标准是一个**直接编辑 JSON 的文本框**；从零配置没有参照 |

| 扫描件 / 图片 | 不支持 | 读图的底子已有：「图片解析 AI」配置档、`ocrImage`，没有管线用它 |
| AI 出答案、采分点、考点 | 有，上传后自动跑 | 可复用 |
| 核答案 | 校对页逐题点开、改、返回列表 | 几百道题点不动；没有批量确认；看不出哪些题最该看 |
| 发布、开通学员 | 有，分散在不同页面 | 没有任何地方告诉你"这门课还差什么才能上线" |
| 考点 | AI 边拆题边建 | 没有合并、改名的入口，重复、粒度不一的考点会拉低自适应练习的质量 |

## 2. 体验原则（所有新功能都按这几条做）

1. **手机优先**：每个流程在手机上都能走完——拍照上传、看进度、核答案、发布、开通。三种宽度都做浏览器测试。
2. **管理员不碰 JSON、不起英文编号**：编号从文件名或学科码自动生成；排序按上传先后；评价标准只暴露几个说人话的开关
   （例如"翻译题按采分点给部分分"），其余从参照学科复制。
3. **AI 生成的东西一律标出来**：题面识别、答案、采分点、考点，凡是 AI 出的都带「AI」标记，人确认过的才去掉。
4. **花钱、耗时的操作先预估、再确认**：开始识别前显示"共 41 页，预计 X 分钟，预计花费约 Y 元"，点确认才开始；做完显示实际花了多少。
5. **告诉人下一步做什么**：每个页面的空状态、完成状态都给出下一步的按钮，不让人自己去找。
6. **出错了能撤**：上传的内容在发布前、没有学员做过时可以整组删除重来（已有能力，页面上要说清楚）。

## 3. 端到端流程：开新课引导 + 上线清单

### 3.1 开新课引导

学科管理页的「开一门新课」进入一个分步流程，每一步显示完成状态，中途离开再回来接着做：

```
① 建课：学科名、参照哪门课（复制题型和评分规则）、满分、时长
② 传资料：Word / PDF / 拍照，可以分几次传
③ 核答案：只看有问题的题，其余整组确认
④ 配组卷：按样卷生成模板草稿，改数字
⑤ 发布：一键发布所有已确认的题
⑥ 开通学员：选人（或全部学员）一键开通
```

### 3.2 上线清单（每门课一张，学科管理页和后台首页都看得到）

示例（公共英语现在的样子）：

> **公共英语**：还差 32 道题待确认 · 7 个内容组未发布 · 0 名学员已开通 · 模考暂时组不出卷（句子翻译、段落翻译缺题）

每一项点进去就是处理它的页面。数据来源全部是现有的（答案状态、发布状态、授权、`exam-readiness` 组卷体检），只是第一次摆到你眼前。

## 4. 功能需求

### A. 新建学科开箱可用

1. **建学科时一并建课程**：表单只有学科名、参照哪门课、满分（默认 100）、考试时长（默认 120 分钟）。
   学科码、课程码自动生成（可改学科码，建了以后不能再改）。学科和课程一次落库，不会出现半成品。
2. **参照已有学科复制能力包**：复制题型、评价标准、四类 AI 提示词、参数；**不复制**题目、考点、组卷模板、学员授权。
   提示词里的原学科名自动替换成新学科名；替换不掉的（管理员自己改过的措辞）原样保留并提示你去看一眼。
   不参照时用一套通用默认（见拍板 1）。
3. **改课程的满分、时长**：学科管理页里直接改；只影响以后组的卷；改完如果组卷模板总分对不上，提示去改模板。
4. **上传页不再要求手填编号**：内容组编号从文件名自动生成、显示名默认取文件名、排序按上传先后，都可改但不必填。

**验收**：手机上建一门参照公共英语的新课，不碰代码，直接能去上传；不参照建出来的学科能力包也读得出来。

### B. 组卷模板

1. **按样卷生成草稿**（主推）：在「配组卷」这一步选一个已上传的、整份的样卷内容组，系统按它的结构生成模板草稿：
   几个部分、每部分哪类题、多少题、每题多少分（分值按试卷说明或你手填）。你只改数字。
2. **表格编辑**：每行一个部分——名称、从哪类题里抽（下拉选，不手打）、抽几题、每题几分、按题抽还是整篇抽
   （页面上用人话说明："阅读、完形这类带文章的选整篇抽"）。
3. **保存时校验**：分值加起来必须等于课程满分（见拍板 3）；抽题来源必须是本学科有的；整篇抽只能按大题类别筛。
4. **保存后立即体检**：每一行显示"可选 N 篇 / N 题，需要 M"，凑不够的标红并说差多少（只提示不拦保存）。
5. 只影响以后组的卷；两人同时改时后保存的被拒并提示刷新；后台改过的模板部署不会冲回去。

**验收**：照公共英语样卷生成的草稿与第 132 页试卷说明一致；新课配好模板、发布题目后学员能组卷。

### C. AI 拆题导入（分两期）

#### C1（第一期）：识别 + 拆题 + 出答案

1. **输入**：Word（任意版式）、PDF（文字版、扫描版）、照片（手机连拍上传，可调页序、删页、重拍）。
2. **流程**：
   ```
   拆页、压缩（浏览器里做）→ 逐页识别成文字（图片解析 AI）→ 整份文字按本学科题型拆成大题 / 篇章 / 题目 / 选项（文本 AI）
   → 预览（每类多少题、存疑的地方、出自第几页）→ 入库 → 自动出答案、采分点、考点 → 进核答案（D）
   ```
3. **怎么跑**（见拍板 4）：识别一份 40 页的资料要几分钟。你在手机上操作，锁屏、切去别的应用很常见——
   **推荐放到服务器后台排队处理，关了页面也继续，做完在后台首页提示你**。
   （实现方式：用定时任务每分钟处理一批，不需要 Cloudflare 的付费功能；代价是比边看边跑慢一点。）
4. **拆题规则**：AI 只能从本学科声明的题型里选；篇章题（阅读、段落填空）把原文和题挂在一起，词库照原样保留；
   跨页的题按整份文字拆、不按页拆；拆不准的题不丢，记成「解析存疑」在预览和核答案时点名。
5. **每道题记住出自第几页**，核答案时显示"原书第 X 页"，你对照手边的纸本。
   **原图一律不保留**（用户 2026-11-07 定：图片太大）：照片和 PDF 只在识别那一刻在内存里过一遍，识别完即丢，
   库里只留识别出的文字。所以识别准不准不能靠事后翻原图，必须由下面「解析成功率保障」在进库之前保证。
6. **手写答案**（你拍来的那种书上写的答案字母）：识别出来作为候选答案，和 AI 答案比对（见 D3）。
7. **生化那条 Word 管线保留**给生化专用（已发布内容在用），别的学科的 Word 都走 C1。
8. **规模**：一次最多 60 页；照片上传前在手机上压缩（压到多大由选型实测定：试长边 1600 和 2400 像素，取准确率达标里最小的——压得太狠，两栏小字会先错）；失败的页单独重试，已成功的不重跑、不重复花钱。

#### 解析成功率保障（原图不留，所以准确率必须在进库前保证）

**第一道关：拍的时候拦住拍坏的**（在手机上、上传之前，不花钱）
- 每张照片当场检查：模糊、太暗 / 过曝、歪斜过大、分辨率不够、页面没拍全（四边被裁）。不合格的标红，提示"这页请重拍"，
  合格之前不让开始识别；

**第二道关：识别之后自动体检**（不需要你看，系统自己查）
- **页码连续**：每页识别时顺带读出书上印的页码（"· 141 ·"），缺页、重页、顺序颠倒先报出来，提示补拍哪一页；
- **结构检查**：题号连续（1、2、3…不跳不重）；每道选择题选项齐全（四个、A–D 不缺不重）；大题题量和书上写的一致
  （如"Multiple Choice (1×25)"就该是 25 题）；段落填空的空号和题数对得上、词库词数对得上；阅读篇章下挂的题数对得上；
- **文字检查**：乱码、不成词的英文（拼写检查器查）、中英文混排异常、一页识别出的字数明显偏少（可能漏了半页）；
- **双重识别**：可疑的页用第二种方式再识别一遍（换个提示词或换个模型），两次结果逐字比，不一致的地方标出来。
  只对可疑页做，花费可控；
- **做题反查**：AI 出答案时，如果某道题它判断"题面不完整 / 选项不成立 / 没有正确选项"，这道题标成可疑——
  这往往就是识别错了，也可能是原书本身的问题，两种都该在你拿着书时看一眼（公共英语这次，第一组第 49、61 题做题时就报了
  "四个选项都不贴切"，当时只记在了核对单里；按这一关，它们会在逐页核对里被高亮）。

**第三道关：拿着书当场核对**（在你手里还有书的时候做，原图不留所以这一步不能拖到以后）
- 识别完立刻进「逐页核对」：按页列出这一页识别出的题，**可疑处高亮**（体检标的、双重识别不一致的、做题反查报的），
  你对照手里的书改字或点"没问题"；没有可疑处的页一键通过；
- 可疑处全部处理完才能入库；某一页错得太多，直接"这页重拍"，只重新识别这一页；
- 入库后每道题仍记着出自第几页、哪些地方是你改过的。

**验收（上线门槛）**：在 C 的选型实测和最终验收里，用你拍的真实照片测出第 0 节的三条数字——题目完整率 100%、
字符准确率 ≥ 99.5%、体检把实际错误找出来的比例（漏报率）。**达不到就不上线 C**，先换模型或加强体检。

**C 的前置：选读图模型**（同时验证上面的三道关）。本机连不到 AI 服务商，所以加一条只手动触发的流水线，拿公共英语扫描件里有代表性的 5 页
（纯选择题、两栏选项、阅读篇章、教学重点中英对照、你拍的带手写答案的照片）跑识别 + 拆题，和已经人工转写好的版本逐字比对，
报出每页字符准确率、题目完整率、错在哪类地方、体检能不能把这些错找出来、耗时、花费。**跑之前先告诉你预计花多少，你同意再跑**；结果写进本文档，你选定模型再开工。

**验收**：用真实任务验收——**你用手机拍公共英语缺的原书第 141–153 页（13 页），在后台走完全流程上线**，
我记下用时、花费、你要改几处；同时一份非生化版式的 Word 能拆出题；生化 Word 结果不变。

### D. 批量核对答案（新增，整条链路里最费人工的一步）

1. **核答案模式**：一题一屏，大按钮「对」「改」，滑动到下一题；手机上可单手完成。
2. **默认只看有问题的**：AI 自己拿不准的、识别存疑的、和原书答案不一致的排最前；没问题的折叠成"其余 N 题，整组确认"。
3. **原书答案页比对**：拍照上传答案页（或书上手写答案的页），自动识别答案、逐题和 AI 答案比对，一致的直接标"已与原书核对"，
   不一致的列出来让你选。这次第二组前 75 题就是这么比出第 6 题的。
4. **答案核对单**：每个内容组可以导出 / 在页面上看一份核对单（同这次的 `ANSWER_REVIEW.md`），拿不准的排最前。
5. 确认留痕：谁、什么时候、依据（原书比对 / 人工确认 / 整组确认），和现在的答案状态、来源一致。

**验收**：一个 200 题的选择题组，有原书答案页时 5 分钟内核完；没有时只需看拿不准的那几道就能整组确认。

### E. 上线：一键发布、一键开通（新增）

1. 上线清单（3.2）里的每一项都能一键处理：发布所有已确认的题（未确认的照旧扣下并说明）、给选定学员或全部学员开通。
2. 开通时可选"以后新建的学员也自动开通这门课"。

### F. 考点整理（新增）

1. 本学科考点列表：每个考点挂了多少题、是不是 AI 建的。
2. **合并**两个考点（题目、学员掌握度记录一起并过去）、**改名**、调整上下级。
3. 不做删除（有学员记录挂着），只做合并。

### G. 学员侧体验（新增）

1. **翻译题的练习反馈**（拍板 9，已定：**每道都 AI 批**）：公共英语有 35 分的翻译题，现在练习里只显示"练习不判分"和参考答案，
   学员很难判断自己写得行不行。改成：练习里交上一道翻译题（词组、句子、段落；以及以后同样按采分点判的题型），
   当场按采分点 AI 批，显示得分、每个采分点答到没有、为什么，参考译文照旧给。批改走模考交卷那同一段代码（`gradeScorePoints`），
   不另写一套；练习里批出的分**只进这次练习的记录和掌握度**，不进成绩报告。
   - **防刷**（已定要加）：同一个学员、同一道题、一字不差的作答不重复批，直接给上次的结果；每人每天上限 100 道
     （正常练习碰不到，到了提示"今天的 AI 批改用完了，明天再来"，作答照样保存）；
   - **AI 出错时**（超时、没读懂）：提示"这次没批出来"、可重试，不显示 0 分；
   - 这条推翻了现在"练习不调 AI"的规矩（CLAUDE.md 四之二"生化模考"里那句），上线时一并改文档。
2. **题量不够时的模考**（见拍板 10）：公共英语的段落填空、阅读理解目前只有一份，每张模考卷这两部分都一样。
   推荐照常开放模考，但在学员端如实提示"本部分题库还在建设中，可能与上次重复"。
3. **拼写单词答错时**：只显示一次标准答案，并说明"本题也接受：……"（现在同一屏重复显示了三次，见第 5 节）。

## 6. 非功能要求与风险

| 项 | 要求 |
|---|---|
| 成本 | 每次识别前显示预估花费；后台显示本月 AI 花费；超过每月上限（见拍板 11）自动停下等你确认；学员练翻译每道都 AI 批，同样的作答不重复花钱、每人每天上限 100 道 |
| D1 写入额度 | 一次导入 500 题约几千行写入，离每天 10 万行很远；重跑只补失败的、不重复写 |
| 隐私 | 拍的照片可能带姓名和笔迹。**原图一律不保留**，识别完即丢，库里只留识别出的文字 |
| 公开仓库 | 后台上传的内容只进数据库，不进仓库 |
| 撤销 | 发布前、没有学员做过的上传内容可整组删除重来；页面上说清楚这个兜底 |
| 权限与留痕 | 只有超级管理员可用；建课、改模板、确认答案、开通都写审计 |
| 测试 | 每期本地全套回归 + 浏览器测试（三种宽度）；AI 相关用替身覆盖"识别乱码、拆题形状不对、某页超时"等情况；替身证明不了识别准确，上线前对真模型跑实测 |
